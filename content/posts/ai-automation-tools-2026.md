**结论先说：** 不会编程、只想把几个常用应用连起来，选 **Zapier**，它连接的应用最多、上手最快，但按「任务」计费，量大了会贵；需要分支、循环、批量处理数据，又不想自己维护服务器，选 **Make**，可视化画布更灵活，同样的预算能跑更多步骤；有一点技术基础、在意数据留在自己服务器上、或者工作流步骤很多，选 **n8n**，可以免费自托管，按整次执行计费。国内应用为主（飞书、企业微信、钉钉）的场景，可以看扣子、Dify 等国内平台。

**说明：** 本文依据三家官网、定价页和官方文档整理（2026 年 10 月查阅），不是实测打分。三家的套餐和额度调整频繁，具体价格请以文中链接的官方定价页为准。

## 先搞懂：自动化工具是干什么的

自动化工具做的事可以用一句话概括：**当 A 发生时，自动做 B、C、D**。「A」叫触发器（收到一封邮件、表单有新提交、每天早上 9 点），「B、C、D」叫动作（把附件存到网盘、在表格里加一行、发一条消息）。

AI 加入之后，动作里多了一类「让大模型处理一下」：把邮件内容总结成三句话、判断客户留言是投诉还是咨询、把会议录音转写成纪要。以前需要人看一眼再决定的环节，现在可以交给模型先处理，人只看结果。

这类工具适合**规则清楚、重复发生**的工作。如果一件事每次都要人判断、流程每次都不一样，先别急着自动化，把流程理清楚比选工具更重要。

## 三款工具总览

| 对比项 | Zapier | Make | n8n |
| --- | --- | --- | --- |
| 定位 | 最简单的应用连接器 | 可视化流程编排 | 面向技术用户的工作流平台 |
| 可连接的应用 | 最多（官方称 8000+） | 较多（数千个） | 较少，但可用 HTTP 节点和代码补齐 |
| 计费单位 | 任务（每个成功执行的动作算一次） | 操作 / 积分（每个模块运行算一次） | 执行（整个工作流跑一次算一次） |
| 免费方案 | 有，每月任务数有限 | 有，每月操作数有限 | 自托管社区版免费；云版付费 |
| 自托管 | 不支持 | 不支持 | 支持（Docker 部署） |
| 写代码 | 可选（Code 步骤） | 可选 | 常用（JavaScript / Python 节点） |
| 上手难度 | 低 | 中 | 中到高 |
| 适合谁 | 个人、小团队、非技术岗位 | 运营、需要复杂流程的团队 | 开发者、重视数据控制的团队 |

官方定价页：[Zapier](https://zapier.com/pricing)、[Make](https://www.make.com/en/pricing)、[n8n](https://n8n.io/pricing/)。

## Zapier：最省心，量大了贵

Zapier 的工作流叫 **Zap**，一条 Zap 由一个触发器和若干动作组成，界面是从上到下的步骤列表，很像填表。它的最大优势是**应用覆盖面**：国外常见的 SaaS 几乎都有现成集成，很多冷门工具也能找到。

AI 方面，Zapier 内置了调用 ChatGPT、Claude 等模型的步骤，还推出了用自然语言描述需求、自动生成 Zap 的 Copilot，以及能自主执行多步任务的 Zapier Agents。对完全不想研究技术细节的人来说，这是门槛最低的选择。

需要注意的地方：

- **按任务计费。** 一条 Zap 有 5 个动作，跑一次就消耗约 5 个任务（具体计数规则以官方说明为准）。工作流一多、触发频繁，费用增长很快。
- **复杂逻辑不够顺手。** 分支（Paths）、循环（Looping）都能做，但流程一复杂，列表式界面就不如画布直观。
- **国内应用支持少。** 飞书、企业微信、钉钉基本只能通过 Webhook 自己对接。

## Make：画布灵活，性价比高

Make（原名 Integromat）的工作流叫 **Scenario**，在一张画布上用圆形模块和连线搭流程，分支、汇合、循环、错误处理都能直接看到。处理「一封邮件里有 10 个附件，逐个识别再汇总」这类批量数据，Make 比 Zapier 顺手。

Make 也提供 OpenAI、Anthropic、Gemini 等模型的模块，并推出了 AI Agents 功能。同样的预算，Make 通常能跑更多步骤，这是很多人从 Zapier 换过来的主要原因。

需要注意的地方：

- **按操作计费。** 每个模块运行一次就算一次操作，循环里的模块会被反复计数，设计流程时要留意。
- **学习成本比 Zapier 高。** 迭代器（Iterator）、聚合器（Aggregator）、数据映射这些概念需要花时间理解。
- **数据存在 Make 的云上**，有严格数据合规要求的场景需要先看条款。

## n8n：能自托管，适合技术用户

n8n 的界面也是节点画布，但更接近开发者工具：每个节点的输入输出都是 JSON，可以随时插入 JavaScript 或 Python 代码节点，用 HTTP Request 节点调用任何有 API 的服务。

它有两个和另外两家本质不同的地方：

1. **可以自托管。** 用 Docker 在自己的 VPS 上部署社区版，不限执行次数，数据不经过第三方。注意 n8n 不是传统意义上的开源软件，它采用 Sustainable Use License（官方称为 fair-code），可以免费自用和内部使用，但不能拿它包装成服务对外售卖，具体以[许可证说明](https://docs.n8n.io/sustainable-use-license/)为准。
2. **按整次执行计费（云版）。** 一个工作流不管有多少个节点，跑一次只算一次执行。步骤多的工作流用 n8n 更划算。

AI 方面，n8n 的 AI Agent 节点可以接入各家模型、向量数据库和工具，适合搭建带知识库的问答、自动分类等流程。本站的 [n8n 教程](/posts/ai-agent-workflow-guide-2026/) 有完整的部署和搭建步骤。

需要注意的地方：

- **自托管要自己维护**：升级、备份、HTTPS、服务器安全都要自己负责。服务器基础可以先看 [Linux 服务器入门教程](/posts/linux-server-beginners-2026/)。
- **现成集成比 Zapier 少**，冷门应用需要自己读 API 文档用 HTTP 节点对接。

## 国内替代：扣子、Dify 和办公套件自带的自动化

如果你的工作主要在飞书、企业微信、钉钉里，上面三家都要通过 Webhook 绕一圈。可以先看这些选择：

| 工具 | 特点 | 适合 |
| --- | --- | --- |
| 扣子（Coze） | 字节跳动的智能体平台，有工作流功能，可以发布到飞书等渠道 | 做对话机器人、简单的 AI 工作流 |
| Dify | 开源的 LLM 应用平台，有工作流和知识库，支持自托管 | 搭建企业内部的 AI 问答、客服，见 [Dify 客服机器人教程](/posts/ai-customer-service-bot-2026/) |
| 飞书、钉钉自带的自动化 | 多维表格、审批等场景内置的自动化流程 | 只在一个办公套件内部流转的任务 |

这类平台以 AI 应用为中心，连接海外 SaaS 的能力不如 Zapier 和 Make，但对国内应用和国内模型的支持更好。

## 三个常见工作流怎么搭

### 场景一：邮件自动总结，推送到聊天工具

- **流程：** 收到带特定标签的邮件 → 大模型总结要点和待办 → 推送到 Slack、Telegram 或飞书群。
- **怎么选：** 用 Gmail 加 Slack 的话，Zapier 几分钟就能搭好；推到飞书群，用 n8n 或 Make 的 Webhook 模块更方便。
- **注意：** 邮件可能含有客户隐私，发给模型前确认公司是否允许。

### 场景二：表单留言自动分类，分配给不同人

- **流程：** 表单（Google Forms、Typeform 或金数据）有新提交 → 模型判断类别（咨询、投诉、合作）和紧急程度 → 写入表格并通知对应负责人。
- **怎么选：** 分类后要走不同分支，Make 的路由器（Router）最直观；量大的话 n8n 更省钱。
- **注意：** 让模型只输出固定的几个类别（比如只允许回答「咨询 / 投诉 / 合作 / 其他」），否则后面的分支会接不住。

### 场景三：每天自动生成数据简报

- **流程：** 每天早上 9 点定时触发 → 从表格或数据库读取昨天的数据 → 模型写一段文字总结 → 发到邮箱或群里。
- **怎么选：** 三家都能做；数据在自己的数据库里，用自托管 n8n 最方便。
- **注意：** 数字的计算交给公式或代码，模型只负责「把算好的数字写成人话」。大模型做算术容易出错，不要让它直接算总数和增长率。

更多办公场景的做法见 [AI 自动化办公指南](/posts/ai-automation-office-2026/)。

## 选择建议

| 你的情况 | 推荐 |
| --- | --- |
| 不会编程，工作流不多，想今天就用上 | Zapier 免费版起步 |
| 流程有分支、循环，要批量处理数据，预算有限 | Make |
| 会用命令行，有 VPS，步骤多、执行频繁 | 自托管 n8n |
| 公司对数据出境、数据存储有要求 | 自托管 n8n 或 Dify |
| 主要在飞书、钉钉、企业微信里工作 | 先看套件自带的自动化和扣子 |

一个实用的做法：先用 Zapier 或 Make 的免费额度把流程跑通，确认真的省时间，再决定要不要付费或迁移到 n8n。三家的工作流不能直接互相导入，迁移需要重新搭建，所以流程多了以后再换成本会变高。

## 控制成本和避免翻车

1. **先算清楚计费单位。** 估算一条工作流每次运行消耗多少任务或操作，乘以每月触发次数，再对照套餐额度。
2. **过滤放在最前面。** 用筛选条件挡掉不需要处理的触发，不要让每封邮件都跑一遍大模型。
3. **模型调用另算钱。** 在工作流里调用 OpenAI、Claude 等模型，通常要用你自己的 API Key，按 token 另外计费，记得在模型平台设置用量上限。
4. **加错误通知。** 授权过期、接口变化都会让工作流悄悄停掉，设置失败时发通知。
5. **关键动作留人工确认。** 对外发邮件、付款、删除数据这类动作，先让工作流生成草稿，人确认后再执行。

## 常见问题

**Zapier、Make、n8n 有免费版吗？**
Zapier 和 Make 都有免费方案，但每月任务或操作数有限，部分高级功能不开放；n8n 的社区版可以免费自托管，云版需要付费。额度以各家定价页为准。

**n8n 是开源的吗？**
它的源代码公开，但采用 Sustainable Use License，不是 OSI 认可的开源许可证。个人和公司内部使用免费，把 n8n 本身作为服务卖给别人需要商业授权。

**不会编程能用 n8n 吗？**
能搭简单的流程，但遇到数据格式转换、接口报错时，有一点 JavaScript 和 JSON 基础会轻松很多。完全零基础建议先用 Zapier 或 Make。

**国内能用这些工具吗？**
Zapier 和 Make 是海外服务，需要能访问它们的网站，连接的也多是海外应用。自托管 n8n 可以部署在任何服务器上。国内应用为主的话，扣子、Dify 或办公套件自带的自动化更合适。

**AI 自动化会不会出错？**
会。模型可能理解错意图、输出格式不稳定。做法是：让模型输出固定格式、加校验步骤、关键动作保留人工确认，并定期抽查结果。

**工作流可以从 Zapier 迁移到 n8n 吗？**
没有一键迁移，需要在 n8n 里重新搭建。好在思路是相通的：触发器、动作、条件分支在三家都有对应的功能。
