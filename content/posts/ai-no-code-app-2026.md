**结论先说：** 不会编程的人，现在可以用 **Bolt.new、Lovable** 这类 AI 应用生成工具，靠打字描述需求做出能用的网页小工具，再一键部署上线。第一次做建议选一个**功能单一的小工具**（比如文案生成器、计算器、落地页），先用 Bolt.new 或 Lovable 的免费额度跑通「描述 → 生成 → 修改 → 上线」全流程。最容易踩的坑是**把 OpenAI 等服务的 API Key 写在网页前端**，任何访客都能看到并盗用，必须放到后端。

**说明：** 本文依据各工具官网和文档整理（2026 年 10 月查阅），不是实测打分。这类工具更新很快，免费额度和价格以官方定价页为准。能做出产品不等于能赚钱，变现部分只讲做法和注意事项，不承诺收入。

## 前置条件

| 项目 | 说明 |
| --- | --- |
| 账号 | Bolt.new 或 Lovable 账号（可用 Google、GitHub 登录）；建议同时注册 GitHub |
| 网络 | 能访问这些海外服务 |
| 预算 | 免费额度足够做第一个小工具；需要调用大模型的功能还要准备模型的 API Key（按量付费） |
| 一个想法 | 功能越单一越好，能用一句话说清「谁、在什么时候、用它做什么」 |

## 先选工具：五款怎么分工

| 工具 | 是什么 | 适合 | 计费方式 |
| --- | --- | --- | --- |
| [Bolt.new](https://bolt.new/) | StackBlitz 出品，浏览器里对话生成全栈网页应用 | 零基础做完整小应用 | 按 token 额度，有免费档 |
| [Lovable](https://lovable.dev/) | 对话生成应用（前身是 GPT Engineer），和 Supabase 数据库集成紧密 | 需要登录、数据库的应用 | 按消息额度，有免费档 |
| [v0](https://v0.app/) | Vercel 出品，擅长生成好看的界面和 React 组件 | 先做界面和落地页 | 按额度，有免费档 |
| [Replit](https://replit.com/) | 云端开发环境，Agent 可以搭建、运行、部署项目 | 需要后端、定时任务的应用 | 订阅加用量 |
| [Cursor](https://cursor.com/) | 本地 AI 编程编辑器 | 有一点基础，想长期维护代码 | 订阅，有免费档 |

**怎么选：** 第一次做，Bolt.new 和 Lovable 二选一就够。需要用户登录、保存数据的，Lovable 接 Supabase 更顺；只做纯前端小工具，两者都可以。等项目变复杂、想自己掌控代码时，把代码同步到 GitHub，再用 Cursor 或 Claude Code 继续改。编程工具的详细对比见 [AI 编程工具横评](/posts/ai-coding-tools-comparison-2026/)。

## 第一步：把想法写成需求

AI 生成的质量，八成取决于需求写得清不清楚。一份好的需求包括五部分：

1. **一句话说明**：这是什么工具，给谁用；
2. **页面和功能**：有几个页面，每个页面上有什么、点了会怎样；
3. **数据**：用户输入什么，要不要保存，要不要登录；
4. **外观**：配色、风格，手机上能不能用；
5. **不要什么**：先不做的功能，防止 AI 自作主张加一堆东西。

以一个「营销文案生成器」为例：

```
做一个营销文案生成器网页，给小商家写商品文案用。
页面：只有一个页面。
- 左侧输入区：产品名称、目标用户、三个卖点、文案风格（专业/活泼/简洁 下拉选择）
- 右侧输出区：显示生成的三条文案，每条旁边有「复制」按钮
- 点击「生成」按钮后显示加载状态
数据：不需要登录，不保存历史。
外观：简洁现代，白底蓝色主色调，手机上左右布局改为上下布局。
暂时不做：用户系统、付费功能、多语言。
先用假数据把界面做出来，生成逻辑下一步再接。
```

最后一句很关键：**先做界面，再接功能**。一次只让 AI 做一件事，出错时容易定位。

## 第二步：生成第一版

1. 登录 Bolt.new 或 Lovable，在首页输入框粘贴上面的需求；
2. 等它生成代码，右侧会出现预览；
3. 在预览里把每个按钮、每个输入框都点一遍，记下不对的地方。

第一版不完美是正常的。不要在第一版就要求它加新功能，先把看到的问题修好。

## 第三步：用对话修改

修改时的原则：**一次只提一个问题，说清楚现象和期望**。

| 不好的说法 | 好的说法 |
| --- | --- |
| 界面不好看，改一下 | 输出区的三条文案挤在一起，每条之间加间距和浅灰色边框 |
| 手机上有问题 | 手机宽度下，右侧输出区被挤到屏幕外，改成输入区在上、输出区在下 |
| 复制按钮坏了 | 点击复制按钮没有反应，期望点击后复制该条文案，并显示「已复制」两秒 |

如果改了几轮反而越改越乱，用工具的版本历史回退到上一个正常的版本，换一种说法重新提。两个工具都支持回退。

## 第四步：接入 AI 功能，保护好 API Key

文案生成需要调用大模型。这一步是新手最容易出安全事故的地方。

**错误做法：** 让 AI 在网页代码里直接写 `apiKey: "sk-..."` 调用 OpenAI。网页前端的代码会完整下载到访客浏览器里，任何人打开开发者工具都能看到你的 Key，拿去刷你的额度。

**正确做法：** Key 只放在后端，前端请求自己的后端接口，由后端去调用模型。可以这样跟 AI 说：

```
接入真实的文案生成功能：
- 新建一个后端接口 /api/generate，在后端调用大模型 API
- API Key 从环境变量读取，绝对不要写在前端代码里
- 前端点击「生成」时请求 /api/generate
- 对接口做简单限制：单次输入不超过 500 字，同一访客每分钟最多 5 次
```

Lovable 通常会用 Supabase 的 Edge Functions 做后端，Bolt.new 也有内置的后端和环境变量配置，具体以工具当时的提示为准。生成后检查一遍：在浏览器里打开开发者工具，搜索你的 Key 的开头几位，确认搜不到。

另外，在模型平台（OpenAI、Anthropic、DeepSeek 等）给这个 Key **设置每月用量上限**，就算出问题，损失也有封顶。

## 第五步：部署上线

| 方式 | 做法 | 适合 |
| --- | --- | --- |
| 工具内置发布 | 点击 Publish / Deploy，得到一个公开网址 | 最快，先给朋友试用 |
| 同步到 GitHub 再部署 | 把代码同步到 GitHub，连接 Cloudflare Pages 或 Vercel | 想绑自己的域名、长期维护 |

第二种方式的完整步骤见 [Cloudflare Pages 教程](/posts/cloudflare-pages-tutorial-2026/)；没有域名的话可以看 [从零搭建个人博客](/posts/free-blog-tutorial/) 里的域名部分。纯静态页面直接部署即可；带后端接口的项目，要确认部署平台支持对应的后端（比如 Supabase 函数仍在 Supabase 上运行，前端部署到哪里都行）。

上线前自查：

- 手机和电脑各打开一次，所有按钮都试过；
- API Key 不在前端代码里，模型平台已设置用量上限；
- 有一个简单的说明或联系方式，用户遇到问题知道找谁；
- 如果收集任何用户信息，写一份简单的隐私说明。

## 常见报错与解决

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 预览白屏 | 代码有报错 | 把预览里或控制台的报错原文复制给 AI，让它修 |
| 免费额度很快用完 | 一次让它改太多、反复重新生成整个项目 | 需求写清楚再发；小改动明确说「只改这个组件」 |
| 改一个地方，别的地方坏了 | AI 修改时影响了其他代码 | 回退到上个版本，提问时说明「不要修改其他部分」 |
| 生成按钮报 401 或 403 | API Key 没配置或配置错 | 检查后端环境变量的名字和值 |
| 部署后功能不能用，预览里能用 | 部署平台没有设置环境变量 | 在部署平台的设置里重新添加环境变量，再部署 |
| 页面在国内打开很慢 | 托管在海外，国内没有节点 | 面向国内用户、对速度要求高的，需要国内服务器和备案 |

## 想收费之前要知道的事

做出一个能用的工具只是开始。真正决定能不能赚钱的是：有没有人搜这个需求、你能不能让他们找到你、他们愿不愿意付钱。几点现实提醒：

1. **先验证需求再加付费功能。** 先免费上线，看有没有人用、用多少次，再决定做不做付费。
2. **收款渠道有门槛。** 海外常用的 Stripe 对开户地区有要求，中国大陆个人能否开通以 Stripe 官方支持国家列表为准；面向国内用户收款要考虑国内支付渠道的资质要求。
3. **成本要算进去。** 每次生成都要付模型费用，免费额度给多了，用户越多亏得越多。
4. **流量靠内容和搜索。** 工具站的流量通常来自搜索引擎，需要持续做内容和 SEO，见 [SEO 优化指南](/posts/seo-optimization-guide/)。更多副业方向见 [用 AI 做副业的 9 种方式](/posts/make-money-with-ai-2026/)。

## 常见问题

**完全不懂代码，真的能做出来吗？**
做一个功能单一的网页小工具是可行的。但遇到报错、需求复杂时，懂一点基本概念（前端、后端、环境变量、数据库）会顺利很多，可以边做边让 AI 解释它写的代码。

**Bolt.new 和 Lovable 选哪个？**
两者定位接近。需要登录和数据库的，Lovable 和 Supabase 的集成更成熟；想快速做一个纯前端工具，两个都可以。各自用免费额度试一个小项目，选顺手的那个。

**生成的代码归谁？能不能导出？**
两个工具都支持把代码同步到 GitHub 或下载，代码可以自己继续修改和部署。商用前看一下各工具的服务条款。

**做好的工具可以放到国内服务器吗？**
可以。导出代码后部署到国内服务器，但用域名对外提供服务需要备案，调用海外模型还要考虑网络和合规问题，也可以换成国内大模型的 API。

**做出来的应用安全吗？**
AI 生成的代码不一定考虑了安全问题。至少检查：API Key 不在前端、数据库开启了访问权限控制（Supabase 要配置行级安全策略 RLS）、对接口做了次数限制。涉及用户隐私和支付的项目，建议请懂技术的人审查。

**免费额度够用吗？**
做一个简单工具通常够用。额度消耗主要来自反复重新生成，需求写清楚、一次只改一处，可以省很多。
