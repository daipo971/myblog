OpenAI 新版《使用政策》将于 **2026 年 11 月 20 日**生效。本站对照 [OpenAI 官方政策原文](https://openai.com/policies/usage-policies/)与 [OpenAI 官方博客](https://openai.com/index/broad-access-through-consistent-standards/)逐条核对：这次修订的核心不是针对普通聊天用户，而是收紧「间接访问」——凡是向第三方直接提供 OpenAI 模型访问的中转平台、模型路由、AI 网关，都必须事先获得 OpenAI 的审批；同时，用模型输出训练竞品模型、提取受保护的推理过程也被明文禁止。先说结论：**只用 ChatGPT 网页或 App 聊天、或用官方 API 给自己的应用供能的用户，不受影响；靠第三方中转站调用 OpenAI 模型的人，服务可能在 11 月 20 日后中断，要提前准备备用方案。**本文只报规则变化与官方申诉路径，不提供任何绕过检测的办法。

## 新规改了什么：官方原文的三处关键变化

以下内容依据 OpenAI 官方使用政策页面（2026 年 10 月 21 日更新、2026 年 11 月 20 日生效）与 OpenAI 同日发布的官方博客《Broad access through consistent standards》，本站 2026 年 11 月 16 日查阅核对。

**第一，中转、路由与网关须事先审批。**新版政策新增「Providing access to our models」一节，原文写明：「If you operate a model-access intermediary platform or other service that enables third parties to directly access OpenAI models, you must obtain our prior review and approval.」也就是说，产品本身就是「把 OpenAI 模型访问权提供给第三方」的服务——模型中转站、模型路由、AI 网关都在此列。官方博客进一步点名，这类服务包括 model routers 或 AI gateways。政策同时划了边界：仅仅因为某个应用集成了 OpenAI 模型来支撑自身功能，并不触发这条审批要求。

**第二，拿模型输出训练竞品，明文禁止。**「Training and developing models」一节写明：不得用 OpenAI 模型或其输出，去生成、准备、筛选或提供训练材料与信号，用于训练「意在替代 OpenAI 模型或服务」的模型。具体包括制作训练数据、训练任务、评分标准、强化学习环境，提供标签、分数、排序、偏好、奖励、修正等训练反馈，以及筛选、过滤、验证训练数据与轨迹。这条禁令不论是自己做、替别人做，还是通过他人做，都适用；即使产品使用或评测中产生的输出事后被拿去训练，也在禁止之列。另外，通过未授权访问、逆向工程或绕过保护措施来提取受保护的推理过程，同样被禁止。

**第三，高风险自动化与未成年人保护收紧。**未经人工审核，不得把模型用于高风险领域的自动化关键行动，包括会实质影响个人权利、安全、基本服务获取的决策、交易、提交等步骤，覆盖关键基础设施、教育、住房、就业、金融信贷、保险、法律、医疗、基本政府服务、产品安全部件、国家安全与移民等领域。国家安全、情报与执法用途，未经 OpenAI 审核批准不得开展。未成年人保护一节也做了澄清，包括禁止 CSAM、诱导、性化未成年人等内容。

## 谁需要审批，谁不需要

| 情形 | 是否须事先审批 | 依据 |
| --- | --- | --- |
| 运营中转站、模型路由、AI 网关，向第三方直接提供 OpenAI 模型访问 | 是 | 政策新增条款，11 月 20 日生效 |
| 聚合多家模型、按量售卖 OpenAI 模型调用的平台 | 是 | 同上；媒体报道点名此类服务为典型例子，但 OpenAI 官方没有点名任何一家 |
| 自己开发应用，调用官方 API 为自家产品功能供能 | 否 | 政策明确：仅因应用集成了模型，不触发审批要求 |
| 只用 ChatGPT 网页、App 聊天 | 否 | 普通产品使用，不属于「提供模型访问」 |
| 企业内部用 API 做自有业务 | 否 | 未向第三方直接提供模型访问 |

关键在「产品是不是访问权本身」：你的产品卖的是「用到 AI 的功能」，不用审批；你的产品卖的就是「调用 OpenAI 模型这个入口」，就要审批。举个例子：一个写作 App 调用 API 帮用户改稿子，不用审批；一个按量计费、让任何人拿着密钥直接调用 OpenAI 模型的转发站，就在审批范围内。至于 [OpenRouter 这类聚合服务](/posts/openrouter-free-models/)，媒体在报道中把它作为可能受影响的例子，但 OpenAI 官方文本没有点名任何一家现有服务——不要把媒体的举例当成官方名单。

## 对国内用户意味着什么

国内用户分三类，影响完全不同。

**第一类：只用 ChatGPT 聊天的人——没有直接影响。**网页端、App 端的正常使用不在新规的审批范围内，订阅与使用方式不变。唯一需要留意的是支付侧的收紧仍在继续：本站 [11 月 7 日的快报](/posts/anthropic-openai-account-policy-update/)写过，OpenAI 在 10 月 31 日更新的帮助说明里明确，同一张银行卡或同一台设备绑定过多订阅时，新的购买可能被直接拦截。

**第二类：用官方 API 的开发者——自用不受影响，转售要小心。**自己申请 API 密钥、给自己的应用或内部业务供能，不需要额外审批。但如果你的服务把 OpenAI 模型访问转售或分发给第三方——比如做了个 API 聚合站、按量卖调用额度——11 月 20 日起就需要 OpenAI 的事先审批。另外注意训练禁令：用 API 输出去蒸馏、训练一个竞品模型，哪怕是自己训着玩，也在禁止之列；研究、开发、评测与基准测试用途仍在允许边界内，但要分清「评测模型」和「训练竞品」的区别。

**第三类：靠第三方中转站调用 OpenAI 模型的人——风险最大。**国内不少用户因为支付与访问门槛，长期走中转站调用 OpenAI 模型。这类服务正是新规的直接目标：11 月 20 日后，未获审批的中转服务在规则上不再合规，存在随时中断的可能。更值得警惕的是官方博客里的一句：OpenAI 正在与合作方协调执法，让限制「跨服务保持有效」（coordinating on enforcement so that restrictions remain effective across services），并引入 SafetyIDs，帮助在调查中区分不同终端用户而不暴露身份。也就是说，违规行为被发现后，限制可能不只停留在一个服务上。建议这类用户在 11 月 20 日前做三件事：第一，确认自己在用的服务方有没有公开说明其合规安排，拿不出说法的就别续费、别囤余额；第二，把重要对话与数据先导出保存；第三，准备好官方渠道的备用方案，例如直接用官方 API 或 ChatGPT，具体路径见本站 [免费 API 入口整理](/posts/free-ai-api-guide/)。至于[代充与共享账号](/posts/daichong-reliability-guide/)，本来就违反服务条款，新规没有给它们留任何空间——付费前先看清那篇里的六个风险点。

## 与 Anthropic 11 月 12 日新规对照：两家在收同一条链

|  | Anthropic（11 月 12 日生效） | OpenAI（11 月 20 日生效） |
| --- | --- | --- |
| 核心动作 | 支付规避、多开绕封、转售代理访问明文可封号 | 中转、路由、网关须事先审批；禁拿输出训竞品 |
| 打击对象 | 盗刷支付、被封后换号、订阅转售 | 未经审批的中间商、蒸馏与推理提取 |
| 普通用户影响 | 正常使用不受影响；申诉期间别注册新号 | 正常使用与自用 API 不受影响 |
| 共同信号 | 平台正在系统性收紧「转售与间接访问」整条链，支付身份与账号身份被绑定核查 | 同左；且执法开始跨服务联动 |

两家政策相隔八天生效，措辞不同，方向一致：以前靠「大家都这么干」混过去的灰色玩法——代充、拼车、多开、中转、转售——正在被逐条写进明文。详细的 Anthropic 条款对照见本站 [11 月 7 日快报](/posts/anthropic-openai-account-policy-update/)。对普通用户来说，规则变化本身不是坏消息：它针对的是中间商与滥用者；但如果你长期依赖灰色链条上的某个环节，链条收紧时最先断的就是你这一环。

## 11 月 7 日的停用报告：未证实，别和新规混为一谈

11 月 7 日前后，社交媒体上出现大量 OpenAI 账号停用的报告，有文章称之为「静默清洗」。必须说清：**截至发稿，OpenAI 没有就这波停用发布任何官方说明或规模数据**，所谓「大规模封号潮」没有官方数据或两家以上独立来源印证，本站不将其作为已证实事件报道。更关键的是时间线：新版使用政策 11 月 20 日才生效，不可能成为 11 月 7 日停用的依据。把两者混为一谈，是这几天不少二手报道的常见错误。真正能确认的只有官方政策文本本身：同卡多订阅限制（据本站 11 月 7 日快报核对的 OpenAI 帮助文档口径）与 11 月 20 日使用政策（本文对照官方原文核对）。

## 被限制了怎么办：只走官方路径

- **ChatGPT / OpenAI 账号**：优先用封号通知邮件里的申诉链接，官方表示这样分流最快；没有邮件或进不去邮箱，用官方申诉表（地址见本站 [11 月 7 日快报](/posts/anthropic-openai-account-policy-update/)），附上账号的 User ID 和 Org ID。
- **API 密钥或开发者账号受限**：走同一申诉通道，说明使用场景（如自用应用、内部业务），并确认自己没有从事转售或训练竞品的行为；收到回复前不要换号重开。
- **共同纪律**：申诉期间不要注册新号、不要买号顶替——按两家的新规，这属于绕封，会把原本可能翻案的申诉直接搞砸；先保数据（能导出先导出），再申诉，耐心等回复。

## 官方还没说清的三件事

1. **没有申请流程。**政策只写了「须获得事先审核与批准」，但没有公布去哪里申请、审批标准是什么、要等多久。截至发稿，政策页面链接的只是一份接收政策更新通知的表单，不是审批入口。
2. **没有宽限期说明。**没有说明 11 月 20 日后未获批的服务会如何处理、有无过渡期。现有服务是否要下线 OpenAI 模型、还是先收到通知，官方都没有说。
3. **没有点名任何服务。**OpenAI 没有公布已获批或未获批的服务名单，也没有公开的执法案例。媒体点名的例子只是推测，不能当作官方名单。

这三点意味着：11 月 20 日当天未必会立刻出现大规模下线，但规则已经生效，风险从「灰色」变成了「明文违规」。对依赖中转服务的用户来说，观望的窗口就是生效日之前的这几天。

## 常见问题

**我只用 ChatGPT 聊天，需要做什么吗？** 不需要。新规不针对普通聊天用户，订阅与使用方式不变。

**我用官方 API 给自己的 App 供能，需要审批吗？** 不需要。政策明确写了，仅因应用集成了模型，不触发审批要求。

**我在用的中转站 11 月 20 日后还能用吗？** 无法保证。未获审批的中转服务在规则上不再合规，是否继续提供服务取决于服务方自己的合规安排。不要囤余额，先导出重要数据。

**用 ChatGPT 的回答训练自己的小模型可以吗？** 如果目标是训练一个替代 OpenAI 的模型，不可以；如果是研究、评测与基准测试，在政策边界内允许。具体边界见上文「拿模型输出训练竞品」一节。

**账号被限制了去哪申诉？** 只走官方申诉表与帮助中心，不要注册新号绕过，也不要轻信声称能「解封」的第三方服务。
