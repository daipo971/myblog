**结论先说：** Anthropic 官方发过一篇复盘，采访了自家产品工程、安全工程、数据基础设施、产品设计、增长市场、法务等团队，讲他们日常怎么用 Claude Code。最值得看的不是「写代码更快」这种老话，而是边界在消失：数据科学家不会 TypeScript，照样交付了 React 应用；法务团队自己做了电话转接系统的原型；市场团队让它批量生成广告变体。六大类用法拆开讲，每类都给出普通人能直接抄的做法。文中效率数字均为 Anthropic 官方自述口径，出处见文末。

![封面图：工程师、法务、市场、数据科学家围着发光的终端协作](/images/how-anthropic-teams-use-claude-code/cover.webp)

## 用法一：读懂代码库，新人上手和日常导航

这是全公司用得最普遍的一类。基础设施团队的新人数据科学家入职时，直接把整个代码库喂给 Claude Code：它先读仓库里的 CLAUDE.md 文件（给 AI 的项目说明），再指出哪些文件相关、讲清数据管道的依赖关系、哪个上游数据源喂给哪个看板——过去这活靠专门的数据目录工具，现在一次对话搞定。

产品工程团队则把 Claude Code 当作任何编程任务的「第一站」：动手前先问它，修这个 bug、加这个功能、做这项分析，分别该看哪些文件。省掉的是人工到处翻文件攒上下文的时间。

**可抄的要点：** 先给项目写好一份 CLAUDE.md，把结构、约定、常用命令说清楚，之后每次提问的质量都会明显变高。这个博客的仓库就在用同一套办法——一份 CLAUDE.md 管着全部发文标准，AI 接手先读它再干活。

## 用法二：写测试和代码审查

写单测和审代码是公认最烦琐的两件事，也是 agentic 工具最先吃下的。

- 产品设计团队用 Claude Code 给新功能写完整的测试，并通过 GitHub Actions 把 PR 评论自动化：格式问题、测试用例重构这类活由 Claude 自动处理；
- 安全工程团队把流程从「设计文档 → 凑合的代码 → 重构 → 放弃写测试」改成：先让 Claude 给伪代码，再带着它走测试驱动开发（TDD），人只定期检查点。结果是代码更可靠、更可测；
- 推理团队还有个巧用法：需要在不熟的语言（比如 Rust）里测功能时，把想测什么讲清楚，Claude 直接按代码库的原生语言把测试逻辑写出来。

**可抄的要点：** 别让它一口气写完整个功能。先伪代码、再测试、后实现，人守住检查点，这是安全团队踩出来的顺序。

## 用法三：线上排障，事故时当军师

生产事故最怕在不熟的代码里靠推理硬撑，这类场景 Claude Code 的提速最明显。

安全工程团队处理事故时，把堆栈跟踪和文档喂给它，让它顺着代码库追控制流。官方自述：原本人工扫描要 10–15 分钟的问题，现在解决速度约为原来的 3 倍。产品工程团队也类似，遇到不熟代码库的 bug，直接描述现象问「能修吗」，看它给的方案再拍板，不必事事等原班人马。

最生动的是数据基础设施团队的一次 Kubernetes 故障：集群停止调度 pod，他们把看板截图发给 Claude Code，它一步步带着他们在 Google Cloud 界面里点菜单，最后定位到 pod IP 地址耗尽，又给出建新 IP 池并挂到集群的确切命令，官方称这次省下约 20 分钟的故障时间。

**可抄的要点：** 报错信息、堆栈、截图都可以直接喂。排障时让它先定位、先给命令，人负责确认再执行。

## 用法四：做原型和新功能，不会语言也能交付

产品设计团队把 Figma 设计文件喂给 Claude Code，再设一个自主循环：它写代码、跑测试、自己迭代，人给抽象问题、最后审方案。有个极端例子：他们让 Claude Code 给它自己写了一套 Vim 快捷键，人类只做了很少的审查。他们还发现一个意外用法——在设计阶段就让它把错误状态、逻辑流、系统状态全画出来，提前暴露边界情况，省掉后面大量调试。

数据科学家那组更能说明边界消失：他们不熟 TypeScript，却用 Claude Code 从零写出完整的 React 应用，给 RL 模型的性能做可视化。在沙箱里一次提示生成整个应用，自己并不理解代码细节；第一版不够就微调提示再来一次。

**可抄的要点：** 原型阶段别纠结代码质量，先让它跑通、能看、能验证想法；提示不满意就改提示重来，比逐行改代码快。

## 用法五：文档和知识管理，把散落的经验变成可问的东西

没有 ML 背景的推理团队成员，靠 Claude 讲清模型相关的函数：官方自述，原本要 Google 搜索一小时的事，现在 10–20 分钟，一项研究时间减少约 80%。

安全工程团队的做法更成体系：让 Claude 把多个来源的文档吃进去，生成 markdown 格式的 runbook（运维手册）和排障指南。这些浓缩后的文档反过来又成为排障时的上下文——真出事故时，查手册比翻整个知识库快得多。底层机制就是 MCP 加 CLAUDE.md：把分散在 wiki、代码注释和老员工脑子里的知识，收成 AI 能直接读的格式。

**可抄的要点：** 先让它把你的文档整理成手册，再让它照着手册干活。同一个工具，整理知识和用知识是两笔收益。

## 用法六：自动化杂活，市场和法务都自己动手

增长市场团队搭了一条 agentic 工作流：处理装着几百条广告的 CSV 文件，找出表现差的，在严格的字数限制内生成新变体。两个分工的子 agent 协作，几百条新广告几分钟生成完，原来要几小时。他们还做了一个 Figma 插件，自动识别画板、替换标题和描述，一批最多生成 100 个广告变体，每批约 0.5 秒，把几小时的复制粘贴压没了。

法务团队的用法最出圈：他们做了电话转接系统（phone tree）的原型，帮同事快速找到对口的律师。一个非技术部门，没等开发资源排期，自己把内部工具的原型做了出来。

**可抄的要点：** 凡是「有明确规则、大批量重复」的活——改文案、换格式、批量生成变体——都值得先想想能不能交给它。判断标准不是难不难，而是规则说不说得清。

## 普通人能直接抄的五条

1. **先写 CLAUDE.md 再提问**：项目说明写一次，之后每次对话都受益，这是全部用法里杠杆最大的一条；
2. **把它当思考搭子，不当代码生成器**：官方复盘的原话结论就是，用得最好的团队是这么定位的。先让它定位文件、给伪代码、画状态图，人再动手；
3. **烦琐事先行**：写测试、审格式、整理文档、批量变体，这些低风险高重复的活最适合先交出去；
4. **排障喂一手材料**：堆栈、日志、截图直接给，别用自己的话转述，转述会丢信息；
5. **非技术岗别等排期**：能把问题和规则描述清楚，就能做出原型。法务的电话树和市场的广告插件都是这么来的。

## 国内怎么用上

Claude Code 需要 Claude 账号（订阅或 API），官方服务未向中国大陆开放，国内用户的使用前提仍是海外账号与相应网络条件，具体开通路径见本站的 [Claude 入门完整指南](/posts/claude-guide/)。没有官方账号的，国内同类终端编程工具可以先看 [Claude Code 与 Codex CLI 对比](/posts/claude-code-codex-cli-2026/)，再对照本文的用法思路，方法论大部分是通用的。

## 常见问题

**完全不会编程，能用 Claude Code 吗？**
能用一部分。Anthropic 内部的法务、市场、数据科学家都不是专业程序员，他们的共同点是能把问题和规则说清楚。但要提醒：生成的东西能不能上线，还是要有人审。原型和内部工具先行，是原文里反复出现的节奏。

**和网页版 Claude 聊天写代码有什么区别？**
Claude Code 是 agentic 编程工具，能直接读整个代码库、改文件、跑测试、在终端里连续干活；网页版更适合单段问答。本文里「自主循环写代码跑测试」「读仓库 CLAUDE.md 导航」这类用法，只有 agentic 形态做得到。

**文中的提速数字可信吗？**
都是 Anthropic 在自家复盘文章里的自述口径（排障约 3 倍、研究时间减少约 80%、事故省约 20 分钟），没有第三方复核。方向可以参考，具体倍数别当承诺，你的项目结构和提示水平影响很大。
