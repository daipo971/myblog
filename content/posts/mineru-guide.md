上一篇 [markitdown 教程](/posts/markitdown-guide/) 解决的是「普通文档快速转 Markdown」，但它有个明确的短板：PDF 里的表格会糊成一片、公式只剩乱码、扫描件（图片型 PDF）直接读不出字。这类硬骨头，要交给今天的主角 **MinerU**——上海人工智能实验室 OpenDataLab 的开源文档解析工具，GitHub 约 **8.32 万星、0.69 万 Fork**（2026 年 11 月 7 日实查），昨天还在更新代码。它把 PDF、扫描图片、Office 文档、电子书解析成结构干净的 Markdown 和 JSON：标题层级、阅读顺序、表格、公式、多栏排版都尽量还原，是给大模型喂资料、搭知识库之前最常用的预处理工具之一。本文口径先说清：安装与解析命令本站在沙箱里实测跑通；效果判断基于自造样例和官方文档，不吹不黑。

![插画：一份带表格和公式的复杂 PDF 文档被送进漏斗，出来变成整齐的 Markdown 文本](/images/mineru-guide/cover.webp)

## 先分清：MinerU 和 markitdown 怎么选

两个工具不冲突，是轻重两档：

- **只是把 Word、PPT、普通 PDF 转成文字喂给 AI** → markitdown 就够了，装起来几十 MB，秒出结果。
- **PDF 里有表格、公式、多栏排版，或者是扫描件** → 用 MinerU。它自带版面分析和 OCR，代价是安装体积大、解析速度慢一个量级。

判断标准一句话：**文档「长得像排版作品」就用 MinerU，只是文字载体就用 markitdown。**

## 四档解析等级，先选档再动手

MinerU 4.x 把解析分成四档（flash、basic、standard、advanced），从快而糙到慢而精：

- **flash**：最快，适合先把大批量文档粗筛一遍、看个大概。
- **basic**：日常够用，普通带图 PDF 的标题、正文、图片能理顺。
- **standard**：表格、公式开始靠谱，本文实测和推荐都以这档为基准。
- **advanced**：最高精度，复杂版面、扫描件质量最稳，代价是最慢、最吃机器。

新手建议：先用 standard 跑一份你最在意的文档看效果，不行再升 advanced，别一上来就用最高档等半天。

## 第一步：不装，先在线试

MinerU 在两个平台有官方在线体验，零安装：

- **ModelScope（魔搭）Studio**：四档齐全，国内打开快，**推荐国内用户先用这个**试。
- **Hugging Face Spaces**：受 ZeroGPU 限制，只有 flash 和 basic 两档。

拿一份你手头最难的 PDF（带表格或扫描页的）上去跑一遍，效果对味了再考虑本地装。在线版适合偶尔用；文档敏感、批量大、要接进自己流程的，再往下看本地部署。

## 第二步：本地安装（官方推荐的 uv 路线）

环境要求：**Python 3.11 到 3.14**（官方示例用 3.12）。默认安装支持在 Windows、Linux、macOS 上用 **CPU 推理**，没有显卡也能跑（就是慢）；有 NVIDIA、AMD、Intel 或苹果芯片的机器可以走加速，追求高吞吐的 NVIDIA 部署另装 `mineru[full]`。

```bash
# 1. 装 uv（已装可跳过），建虚拟环境
pip install uv
uv venv .mineru --python 3.12

# 2. 激活环境
source .mineru/bin/activate          # Linux / macOS
.\.mineru\Scripts\Activate.ps1       # Windows PowerShell

# 3. 安装 MinerU 4.x
uv pip install -U "mineru>=4.0,<5"
```

本站沙箱实测说明：这一步会拉一批依赖（含推理框架），体积以 GB 计，网络不稳时容易中途失败，重跑同一条命令续装即可；公司网络或校园网建议开代理或换时段。

**国内用户必看——模型下载源**：第一次解析时 MinerU 要下载解析模型（版面、OCR、公式等几个模型）。默认从 Hugging Face 拉，国内经常卡住或超时；把模型源切到 ModelScope（魔搭）再跑第一次解析，是国内部署最常见的一个坑，具体环境变量写法以官方文档「模型源」一节为准，装之前先去对一眼，别对着超时干等。

## 第三步：第一次解析

```bash
mineru-kit parse 你的文档.pdf -o 输出.md --tier standard
```

- 输入不止 PDF：扫描图片、`.doc/.docx`、`.ppt/.pptx`、`.xls/.xlsx`、电子书（epub）、网页（html）都在支持列表里。
- 输出除了 Markdown，还会给结构化的 JSON（带页码和块定位），要接 RAG、做引用溯源的用 JSON 那份。
- 想要图形界面：`mineru-kit webui` 起本地网页版，拖文件进去解析，适合不想碰命令行的。
- 批量和程序化：它提供本地服务与 Python SDK（先 `mineru server start` 再用客户端调用），要把解析接进自己系统的走这条线，本文不展开。

**本站沙箱实测（自造样例）**：一份包含标题、段落、三行表格和一行公式的单页 PDF，用 basic 档在纯 CPU 环境解析。结果：标题被正确标成二级标题、段落完整、**表格被还原成标准 Markdown 表格，三行数据一格不错**——这正是轻量工具做不到的部分。公式也转成了 LaTeX 形式，但有个细节翻车：原文里的 `^` 被认成了 `∧`，公式结构是对的、符号能认错，关键公式仍要人工核对。耗时参考：首次运行先下载模型（沙箱里约 3 分钟），之后这单页解析约 3 分钟（沙箱 CPU 较弱，家用电脑会快些；文档越厚、档位越高越久）。

**效果预期（把话说在前面）**：它对论文、财报、教材这类「正规排版」的文档效果最好；表格能还原成 Markdown 表格、公式能转成 LaTeX，这是它和轻量转换工具拉开差距的地方。但别神化：合并单元格特别多的花哨表格、手写批注、排版混乱的宣传单页，仍然会出错——解析完的关键文档，表格数字要抽查核对，这是用任何解析工具都省不掉的一步。

## 输出长什么样，接知识库前注意两点

一次解析会产出一组文件，而不只是一个 Markdown：正文 `.md`、带页码与块定位的结构化 JSON、从文档里抽出的图片文件。两个实操提醒：

1. **搬文件要整组搬**：Markdown 里的图片是相对路径引用，单独把 `.md` 拷走，图片就全丢了；要分享或入库，连同图片文件夹一起打包。
2. **切分按标题层级切**：喂给 RAG 或知识库时，优先按它还原出的标题层级切块，比按固定字数硬切更不容易把上下文切碎；表格尽量整块保留，表格被切成两半时，大模型读到的数字很容易对错行。

## 许可证：能商用，但有两条线

MinerU 用的是**基于 Apache 2.0 的自定义许可证**（和 [Kimi K3.1 Pro 权重](/posts/kimi-k3-1-pro-local-deploy/) 的思路类似）：

- 一般商用**不需要**另买授权；
- 但你和关联方合并计算，**月活超过 1 亿**，或**月营收超过 2000 万美元**，就必须另谈商业授权——普通个人和中小团队离这条线很远；
- 基于它给第三方提供**在线服务**的，要在产品界面或公开文档里**显著标注使用了 MinerU**，这条容易被忽略，做产品的注意。

## 常见问题

**和 markitdown 到底装哪个？**
都装也行，不冲突：日常转换走 markitdown（快），遇到带表格公式的 PDF 和扫描件再喊 MinerU。存储紧张的只留一个，按你的文档类型选。

**扫描件（图片型 PDF）能处理吗？**
能，这是它的主场之一：内置 OCR 和版面分析，扫描版书籍、影印合同这类没有文字层的 PDF 正是为它准备的。清晰度太差的扫描件先提高扫描分辨率再解析。

**没有显卡能用吗？**
能，默认安装就是 CPU 推理。代价是速度：几十页的文档可能要等几分钟到几十分钟（看档位和机器），先用 flash/basic 验流程、正式跑再上 standard。长期批量跑的建议上显卡或云端 GPU。

**解析结果能直接喂给知识库吗？**
能，它的输出本来就是为 RAG 设计的：Markdown 给人看和切分，JSON 带页码块定位做引用。但建议保留原 PDF 备查，解析有误差时能回溯原文核对。
