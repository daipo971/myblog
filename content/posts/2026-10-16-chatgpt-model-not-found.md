今天（10 月 15 日起）大批 ChatGPT 网页端用户反馈：发消息直接弹 **"Model not found"**，新旧会话全挂。OpenAI 状态页已确认遇到问题正在修复。别慌，原因找到了，有解。

## 发生了什么

- **10 月 14 日**：OpenAI 从 ChatGPT、ChatGPT Work、Codex 全线**退役 GPT-5.5**（9 月 14 日更新日志已预告）
- **10 月 15 日**：报错集中爆发。OpenAI 开发者社区三个帖子、V2EX 帖（19 条回复）、凤凰网都跟进了
- 症状：网页端和桌面端 Chat 模式发不出消息；模型选择器里只剩 GPT-6 和 GPT-5.6 Sol；但手机 App、Codex、Work 模式很多人正常

## 根本原因

你的旧会话、自定义 GPT、已保存的 agent **还在指向已经不存在的 GPT-5.5**，服务器找不到这个模型，直接报错。这不是你账号的问题，是模型下线。

## 解法

**解法 1：新开会话（对大多数人有效）**
新开一个对话，模型选择器里手动选一个列表中的模型（比如 GPT-6），或者直接保持 Auto。旧的 GPT-5.5 会话就别用了。

**解法 2：Codex 用户改配置**
把配置里所有 `gpt-5.5` 改成 `gpt-5.6-sol`：已保存的模型设置、自定义 agent、定时任务、脚本，一个都别漏。用 API key 登录 Codex 的目前不受影响。

**解法 3：新会话也报错？（挂代理用户高发）**
如果新开会话依然报错，大概率是网络环境被风控了。网友实测有效的几个偏方（非官方，按顺序试）：

1. **时区对齐**：浏览器时区和代理 IP 所在时区不一致会被标记可疑。把系统/浏览器时区改成跟代理节点一致，刷新重试
2. **换代理节点**：切一个干净的节点
3. **换浏览器或改 UA**：Chrome 换 Edge，或在开发者工具里修改 User-Agent，不少人这样恢复了
4. **手机 App**：很多人反馈网页端挂了但手机 App 正常，先顶着用

## 哪些不受影响

- **OpenAI API**：这次退役不涉及 API
- **API key 登录的 Codex**：暂时保留 GPT-5.5 访问
- 免费账号有人反而正常——说明这是服务端按账号/会话灰度出的问题，不是全挂

## 一句话

这次不是封号也不是网络问题，是 GPT-5.5 退役的"后遗症"。新开会话选 Auto，90% 的人当场恢复；剩下的 10% 去查时区和代理。

## 对普通用户意味着什么

- **模型退役会越来越频繁。** OpenAI 更新模型的节奏很快，旧模型下线后，依赖它的旧会话、自定义 GPT 和自动化脚本都可能报错。遇到类似报错，先想到「是不是模型下线了」，再去查网络问题。
- **重要的提示词和设置要自己备份。** 自定义 GPT 的指令、常用提示词保存在本地一份，模型切换后可以快速重建。
- **用 API 或 Codex 跑自动化的人，配置里别写死旧模型名。** 关注 OpenAI 的更新日志，提前替换。
