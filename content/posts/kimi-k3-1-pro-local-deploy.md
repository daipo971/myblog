## 权重出了什么：先对齐官方模型卡

依据月之暗面官方 Hugging Face 模型卡（2026-11-05 查阅），Kimi K3.1 Pro 的公开版本是这样一个模型：

- **架构**：混合专家模型（MoE），总参数 2.8 万亿，每次回答只激活约 1040 亿参数；896 个专家，每个 token 选 16 个，另有 2 个共享专家；
- **上下文**：1,048,576 token，一次能吞下一整套程序码库加文件；
- **层数与注意力**：共 93 层，其中 24 层把全注意力换成了 Gated DSA 稀疏注意力，长上下文更省算力；
- **多模态**：文字与图片输入，视觉编码器 MoonViT-V2（4.01 亿参数）；
- **精度**：专家权重为 MXFP4、激活为 MXFP8，属于量化感知训练的产物——也就是说，4-bit 不是事后压出来的，训练时就按这个精度设计；
- **推理引擎**：官方模型卡推荐 vLLM、SGLang、TokenSpeed 三种。

一个必须先说明的差异：**公开权重版和 API 版在网路安全任务上可能不完全相同。**月之暗面在发布时就说过，为了控制进攻性网路能力，开源版本去掉了相关训练资料。模型卡上的 ExploitBench 为 74.7 分，而内部未过滤版本在自家 xdev-bench-hard 上是 81.0 分——拿公开权重去测安全任务，别直接拿 API 版的成绩去对。

## 授权到底允许什么：读原文，不听二手说法

授权全文就在权重仓库的 LICENSE 档案里，名字叫 Kimi K3.1 Pro License，版权方为 Moonshot AI。逐条翻译成人话：

2. **模型即服务（MaaS）门槛**：如果你或你的关联公司经营「把模型推理或微调能力开放给第三方」的业务，且你与关联公司合计**任意连续 12 个月营收超过 2000 万美元**，那么在把软体或衍生作品用于任何商业目的之前，必须先和月之暗面签一份单独协议。注意：这里的「模型即服务」不包括「把模型能力只嵌在某个具体功能里的终端产品」，也不包括「单纯转发请求到别人托管的模型」。
3. **超大产品署名门槛**：如果你的商业产品或服务**月活跃用户超过 1 亿，或月营收超过 2000 万美元**，产品介面上必须显著标示「Kimi K3.1-Pro」。
4. **豁免**：上面第 2、3 条不适用于两种情况——（a）内部使用，即不把软体、输出或底层能力提供给第三方；（b）透过月之暗面官方产品或认证推理伙伴使用。
5. **不担保**：软体按「现状」提供，不附任何明示或默示担保。

翻译成普通人的结论：**个人研究、小团队内部用、做产品卖给客户，只要不触发上面两个美元门槛，都不需要另外付钱或申请。**真正要签协议的，是年营收 2000 万美元以上的模型托管生意——那不是这篇文章的读者。商用前仍建议把 LICENSE 原文存档，授权问题可写信到 license@moonshot.ai 询问。

## 前置条件：先算帐，别先下载

本地部署 Kimi K3.1 Pro 的门槛不在技术，在硬件和频宽。动手前逐项确认：

- **GPU**：官方 vLLM 配方给的基准配置是**一组 8 张 GPU 的张量并行**——一台 B300 节点，或两个 GB300 托盘。没有这个量级的卡，部署就无从谈起；单卡、双卡、消费级显卡不在讨论范围内。
- **硬盘**：权重档案体积是 TB 级（第三方整理约 1.56 TB，96 个 safetensors 分片；下载前请以仓库档案页实际大小为准），加上缓存和日志，至少预留 2 TB 可用空间。
- **网路**：从 Hugging Face 拉 TB 级档案需要稳定高速的下载通道，下载中断可续传，但请先估好时间成本。
- **系统**：一台能装 NVIDIA 驱动与 CUDA 的 Linux 服务器，Python 3.10 以上；vLLM 官方配方使用 CUDA 13.4 的 `vllm/vllm-openai:kimi-k31-cu134` 映像。
- **替代路线**：如果你只是想「自己跑一个开源模型玩玩」，不要选 K3.1 Pro——去跑能在单卡上跑的小模型。K3.1 Pro 的本地部署是给有集群的团队准备的。

对照一下成本：同样的模型走官方 API 是每百万 token 输入 2 美元、输出 10 美元（`kimi-k3.1-pro`），对绝大多数人来说，API 比自建集群便宜得多。本地部署的价值在资料不出内网、长期大流量摊薄成本、以及可以微调——三者都不沾，就别部署。

## 部署步骤：用 vLLM 把服务跑起来

以下步骤依据官方模型卡与 vLLM 官方配方整理（2026-11-05 查阅），未经实机验证——跑通后请以你环境的实际输出为准，遇到报错先看文末的常见问题。

### 第 1 步：准备环境

在一台具备 8 张 B300 级 GPU 的 Linux 节点上，安装 NVIDIA 驱动与 CUDA，并确认 `nvidia-smi` 能看到 8 张卡。建议用官方配方指定的容器映像，省去驱动与依赖对不上的麻烦：

```bash
docker pull vllm/vllm-openai:kimi-k31-cu134
```

不用容器的话，装 vLLM 时请确认版本支援 Kimi K3.1 Pro（配方发布于 2026-11-02，旧版 vLLM 跑不了这个模型）。

### 第 2 步：下载权重

权重仓库不需要申请权限，直接用 Hugging Face 官方工具下载：

```bash
pip install -U "huggingface_hub[cli]"
hf download moonshotai/Kimi-K3.1-Pro
```

下载完成后核对档案完整性：分片数量与大小应与仓库档案页一致，缺片或损坏会在载入时报错，不要跳过这一步。

### 第 3 步：启动推理服务

用 8 卡张量并行启动 vLLM 服务（TP8 是官方配方的基准配置；长上下文或多会话场景可参考配方中的 DCP8 配置）：

```bash
vllm serve moonshotai/Kimi-K3.1-Pro \
  --tensor-parallel-size 8 \
  --max-model-len 262144
```

`--max-model-len` 可依显存与场景调整：模型本身支援 1,048,576 token，但开满上下文会吃掉大量 KV 缓存，第一次跑建议先用 262144 验证服务能起来，再往上加。

### 第 4 步：验证服务

服务起来后，用官方配方里的请求方式测一次（预设走 OpenAI 相容介面）：

```bash
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "moonshotai/Kimi-K3.1-Pro",
    "messages": [{"role": "user", "content": "用两句话解释什么是稀疏注意力。"}],
    "temperature": 0.7,
    "top_p": 0.95
  }'
```

拿到正常回复，说明服务已通。接下来再测两件事：一是**长上下文**（喂一篇长文件，看会不会在中途报显存不足）；二是**多轮对话**（Kimi K3.1 Pro 要求把上一轮的完整 assistant 讯息原样传回，包括思考内容与工具呼叫，不只传 content——客户端要按这个规则写，否则多轮效果会变差）。

### 第 5 步：接进你的应用

服务跑通后，它就是一个 OpenAI 相容的 `/v1/chat/completions` 端点：把原来指向 API 的 base_url 换成你自己的 `http://localhost:8000/v1`，模型名填 `moonshotai/Kimi-K3.1-Pro` 即可。注意两点：

- **只支援思考模式**：K3.1 Pro 预设就是「先想再答」，不要试图关掉思考；官方 API 会拒绝关闭思考的请求，本地部署也请保持预设行为。
- **思考强度**：官方 API 用顶层 `reasoning_effort` 栏位（`low`／`high`／`max`，预设 `max`）；本地部署的对应参数请查你所用 vLLM 版本的文件，不要凭印象填。

## 常见问题

**Q1：只有 1～2 张卡，能跑吗？**
不能按官方配方跑。TP8 是基准配置，卡数不够时载入就会失败或直接 OOM。不要尝试把 2.8 万亿参数往小显存里硬塞——换小模型才是正解。

**Q2：下载到一半断了怎么办？**
`hf download` 支援续传，重新执行同一条命令即可。先确认磁碟空间够（TB 级），空间不足造成的损坏分片要删掉重下，不要带病载入。

**Q3：启动时报不支援的模型架构？**
vLLM 版本太旧。Kimi K3.1 Pro 的配方是 2026-11-02 才发布的，升级到支援它的版本（或直接用官方容器映像 `vllm/vllm-openai:kimi-k31-cu134`）再试。

**Q4：显存不足（OOM）怎么调？**
先把 `--max-model-len` 调小（例如从 1,048,576 降到 262144），再看 KV 缓存占用；长上下文场景改用配方的 DCP8 配置，把 KV 缓存分片到 8 张卡上，而不是每张卡复制一份。

**Q5：商用要不要给月之暗面付钱？**
按授权原文：一般商用不用。只有「模型即服务」业务且合计年营收超 2000 万美元，才需要先签单独协议；超大产品（月活 1 亿或月营收 2000 万美元）要显著标示「Kimi K3.1-Pro」。内部使用豁免这两条。

**Q6：公开权重版和 API 版效果一样吗？**
不完全一样。月之暗面已说明开源版本去掉了网路进攻相关训练资料，安全任务分数因此不同；一般程序、文件、Agent 任务以模型卡成绩为准，但独立评测尚未出现，关键场景请自己跑一遍再上线。

**Q7：不想自己搭集群，还有什么办法用上它？**
走官方 API（`kimi-k3.1-pro`，输入 2 美元／输出 10 美元每百万 token），或等第三方托管与认证推理伙伴上线。授权上，透过官方产品与认证伙伴使用是豁免额外条件的。
