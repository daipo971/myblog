过去一年，AI编程工具的发展速度比我见过的任何技术都快。

去年大家都在用 Cursor 和 Copilot 做代码补全，今年已经进入了**"AI自主编程"**的时代。你只需要描述需求，AI就能帮你写出完整的代码、跑测试、修bug。

Claude Code 和 Codex CLI 是2026年最让人兴奋的两个工具。我用了一段时间，分享一下真实感受。

---

## 第一代：Cursor — 智能代码编辑器

如果你还没用过 Cursor，先去看看我之前写的 [Cursor教程](/posts/cursor-ai-tutorial-2026/)。它仍然是很多人的日常主力。

**核心能力：**
- Tab补全：AI预测你接下来要写什么，按Tab接受
- Cmd+K：选中代码，输入修改指令
- Composer：多文件编辑，一次改多个文件

**适合场景：** 日常开发、写代码、改代码。

Cursor 强在跟开发流程的融合——它不是"你写好需求AI生成"，而是**你在写代码的过程中AI辅助你**。这是目前最自然的AI编程方式。

但 Cursor 有一个天花板：**它需要人亲自动手写第一行代码。** 如果你让一个完全不会编程的人用Cursor，他还是写不出一个完整的项目。

---

## 第二代：Claude Code — 终端里的AI工程师

Claude Code 去年年底发布后，迅速成为开发者圈最热门的话题。

它不是一个编辑器插件，而是一个**终端工具**。你在终端里运行 `claude` 命令，它就接管了整个终端，能读你的文件、写代码、跑命令。

### 安装

```bash
npm install -g @anthropic-ai/claude-code
```

然后在项目目录里运行 `claude` 就开始了。

### 实际体验

我让它做一个简单的TODO应用——从前端到后端全栈：

```
> claude
# 我输入：帮我创建一个全栈TODO应用，前端用React，后端用Express + SQLite
```

然后Claude Code就开始工作了：创建项目结构、写前端组件、写后端API、写数据库schema、安装依赖、启动开发服务器——全程不需要我动一个手指。

大概3分钟后，浏览器里就出现了一个可以用的TODO应用。**这中间我没有写过一行代码。**

### 核心能力

- **读取整个项目上下文** — 它能理解项目的全部文件，不会"忘记"之前做了什么
- **自动执行命令** — 装依赖、跑测试、构建，全自动完成
- **多文件编辑** — 一次改几十个文件都没问题
- **Git集成** — 自动创建有意义的commit信息

### 适合场景

- 快速搭建项目原型
- 处理复杂的跨文件重构
- 写单元测试和文档
- 技术债清理

### 局限性

Claude Code 跑在云端，你的代码会经过Anthropic的服务器。如果你是做保密项目，可能需要注意。

另外它的使用成本不低——按token计费，一个大型任务可能花几美金。

## 第三代：Codex CLI — 开源AI编程终端

Codex CLI 是 OpenAI 今年推出的开源工具，跟Claude Code思路类似，但有一些关键差异。

### 安装

```bash
npm install -g @openai/codex
```

同样是终端工具，但 Codex CLI 最大的特点是**开源**。

### 核心能力

- **隐私优先** — 可以在本地运行（配合Ollama），代码不出你的电脑
- **多模型支持** — OpenAI、Claude、本地模型都能用
- **沙箱执行** — 代码在沙箱里运行，不会影响你的系统
- **自动修复** — 代码出错会自动分析和修复

### 实际体验

跟Claude Code类似，但我觉得 Codex CLI 在**"保持代码一致性"**方面做得更好。如果你已经有一个代码库，让 Codex CLI 加新功能，它会先理解你的代码风格再动手，改出来的代码跟原来的风格一致。

沙箱执行也是一个很有安全感的特性——AI写的代码先在一个隔离环境里跑，不会乱动你的文件。

### 开源优势

因为是开源的，社区已经贡献了很多插件扩展：
- 支持对接各种AI模型
- 自定义代码审查规则
- 集成CI/CD流程

## 三个工具怎么选

| | Cursor | Claude Code | Codex CLI |
|---|---|---|---|
| 定位 | AI代码编辑器 | AI编程助手 | 开源AI编程终端 |
| 上手难度 | 低 | 中 | 中 |
| 隐私性 | 一般 | 一般 | **高（可本地运行）** |
| 价格 | $20/月 | 按量计费 | **免费开源** |
| 最适合 | 日常编码 | 全栈快速开发 | 隐私敏感项目 |
| 模型 | 多模型 | Claude | 多模型+本地 |

我的建议是**三个都装，各用各的**：

- **写功能代码时用 Cursor** — 最自然的编码体验
- **搭建新项目或大规模重构时用 Claude Code** — 效率最高
- **处理敏感项目或不想花钱时用 Codex CLI** — 开源免费，本地运行

## 未来：AI编程的方向

从Cursor到Claude Code再到Codex CLI，我看到一个清晰的趋势：

**AI正在从"辅助工具"变成"协作者"。**

以前是"你写代码，AI帮你补全"。
现在是"你描述需求，AI帮你写代码"。
未来可能会是"你有想法，AI帮你实现"。

但这不代表程序员不需要学编程了。恰恰相反——**理解代码的能力比亲手写代码的能力更重要。** 因为你需要检查AI写的代码、告诉AI该怎么改、在AI搞不定的时候接手。

所以如果你想学编程，我的建议跟以前一样：**先把手写代码的基础打牢，再用AI提升效率。** 这叫"AI增强，不是AI替代"。
