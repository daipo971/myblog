**先说结论：Claude Code 是 Anthropic 推出的终端编程智能体，装好之后不用学新编辑器，在命令行里用一句话交代任务，它自己读代码、改文件、跑命令、看报错再修，最后把改动交给你审查。**它不提供逐行代码补全，日常敲代码仍靠编辑器；它擅长的是「交代一个任务，等一个结果」：修 Bug、加功能、重构、写测试、升级依赖，这类跨多个文件的活。想用它只有一个门槛：需要 Claude 的付费订阅（Pro、Max、Ultra）或 API 账号，免费版不含 Claude Code。本文依据官方文档整理，查阅时间 2026 年 11 月 21 日；命令与价格以链接里的官方页面为准。

## 1. 核心底层逻辑与原理解析

理解 Claude Code 先要理解它和补全工具的区别。补全工具猜你下一行写什么；Claude Code 走的是「智能体循环」：你给目标，它自己拆步骤、调用工具、检查结果、修正错误，循环到任务完成或需要你拍板为止。

```
你说任务（例如：把登录接口改成支持邮箱验证码）
        │
        ▼
读代码、定计划 ──→ 改文件、跑命令 ──→ 看报错、再修改
        ▲                              │
        └────── 改动交给你审查 ──────────┘
```

这个循环能跑起来，靠四样东西：

- **读整个项目，不是只读一个文件。** Claude Code 启动后会扫描工作目录，用搜索工具定位相关文件，再决定改哪里。项目越大，第一次理解花的时间和 token 越多。
- **CLAUDE.md 是它的长期记忆。** 在项目根目录放一个 `CLAUDE.md`，写清项目结构、代码规范、常用命令，它每次启动都会读。相当于给新同事写一份入职手册，写一次，次次生效。
- **权限确认是默认状态。** 改文件、跑命令之前它会先征求你同意，你可以按命令设白名单，也可以按 Shift+Tab 切换权限模式。默认的谨慎模式是它敢动你代码的前提。
- **计划模式先想清楚再动手。** 大任务先让它只读代码、给出方案，你确认之后它再改。改错的代价比多问一句高得多，计划模式就是为这个准备的。

一句话总结它的定位：**编辑器是你写代码的地方，Claude Code 是你派活的地方。** 两者不冲突，很多人的日常组合就是编辑器写日常代码、终端智能体做大任务。本站已有 [Claude Code 与 Codex CLI 对比](/posts/claude-code-codex-cli-2026/)，讲了终端智能体与编辑器 Agent 的分工；[AI 编程工具横评](/posts/ai-coding-tools-comparison-2026/) 则把几类工具放在一起比了一遍。

## 2. 核心方案与多维对比横评

### 2.1 Claude Code、Cursor、Codex CLI 怎么选

| 对比维度 | Claude Code | Cursor | Codex CLI |
| :--- | :--- | :--- | :--- |
| **形态** | 终端命令行智能体 | AI 代码编辑器 | 终端命令行智能体 |
| **背后模型** | Claude（Opus 5.5 为默认） | 可选多个模型 | OpenAI 模型 |
| **最适合** | 跨文件大任务、修 Bug、重构、跑测试 | 日常边写边改、逐行补全 | 与 Codex 同类，适合已有 ChatGPT 订阅的人 |
| **改代码方式** | 读全项目、自己改多个文件并跑命令验证 | 选中代码改片段，也有 Agent 模式 | 与 Claude Code 同类 |
| **记忆机制** | 项目根目录 `CLAUDE.md` | 项目规则文件 | 类似的指令文件 |
| **扩展** | MCP、自定义斜杠命令、子代理、Hooks | 规则与 MCP | MCP、插件 |
| **计费** | 含在 Claude 订阅里，或按 API token 计费 | 订阅制 | 含在 ChatGPT 订阅里，或按 API 计费 |

选型结论很直接：**已经订阅了谁，就先用谁的终端智能体。** 有 Claude Pro 或 Max，用 Claude Code 不用再花钱；有 ChatGPT Plus 或 Pro，Codex CLI 同理。日常写代码的主力位置仍然留给 Cursor 这类编辑器，终端智能体负责「派活」。三者的边界正在变模糊，编辑器的 Agent 模式也在往「交代任务等结果」走，但交互习惯仍然不同：喜欢在终端里工作的人用 Claude Code 更顺手。

### 2.2 两条付费路线：订阅还是按量

Claude Code 本身没有单独售价，费用走两条路线：

| 路线 | 价格（美元，官方定价页） | 适合谁 | 要注意什么 |
| :--- | :--- | :--- | :--- |
| **Pro 订阅** | 20/月，年付约 17/月 | 一周用几次的个人开发者 | 与网页版 Claude 共用额度，有 5 小时与每周用量上限 |
| **Max 订阅** | 100/月 | 每天长时间用的人 | 约 5 倍 Pro 用量，另含每月 100 美元 API 额度 |
| **Ultra 订阅** | 200/月 | 跑超长任务的人 | 约 10 倍 Pro 每周用量，无 5 小时上限（需验证账号） |
| **API 按量** | 按 token 计费，无订阅 | 自动化、CI、团队按量结算 | 无用量上限，只有你自己设的消费上限 |

补充两点：第一，2026 年 10 月 30 日 Anthropic 把 Max 20x 改名为 Ultra，老用户自动迁移、价格不变，网上旧文章里的 Max 20x 就是现在的 Ultra。第二，免费版 claude.ai 不含 Claude Code，装好了也登不进去。

### 2.3 API 按量到底多少钱

按 API 计费时，价格取决于会话用的模型（每百万 token，官方定价页，查阅时间 2026-11-21）：

| 模型 | 输入 | 输出 | 适合 |
| :--- | :--- | :--- | :--- |
| Opus 5.5（默认） | 4 美元 | 20 美元 | 最难的架构与多步推理 |
| Sonnet 5.5 | 2 美元 | 10 美元 | 日常大多数编码任务 |
| Haiku 5.5 | 0.10 美元 | 0.50 美元 | 简单改动、子代理跑的杂活 |
| Fable 5.2 | 8 美元 | 40 美元 | 要求最高的任务 |

Anthropic 官方成本页给出的企业平均数是：每位开发者每个活跃日约 13 美元，每月约 150–250 美元，90% 的用户每天低于 30 美元。这是企业部署的平均值，不是个人账单的承诺。个人用户最实在的控费办法在第 3 节最后：随时用 `/usage` 看消耗，简单任务切到 Haiku 5.5。

## 3. 手把手完整实战流程

### 步骤一：前置条件检查

开始之前确认三件事：

- **系统要求（官方文档）：** macOS 13.0+、Windows 10 1809+、Ubuntu 20.04+、Debian 10+ 或 Alpine Linux 3.19+；4GB 以上内存；x64 或 ARM64 处理器；需要联网。Git 可选装，但建议装上，没有 Git 它很多版本管理功能用不了。
- **账号：** Claude Pro、Max、Ultra、Team 或 Enterprise 订阅其一，或者 Claude Console（API）账号，或者亚马逊 Bedrock、谷歌云、微软 Foundry 这类云厂商渠道。免费版不行。
- **一个项目：** 准备一个真实项目目录。第一次练手建议用自己熟悉的小项目，不要直接拿线上生产代码开刀。

### 步骤二：安装

官方推荐原生安装脚本，也可以走包管理器或 npm。三条经过核实的命令（以官方安装文档为准）：

```bash
# macOS、Linux、WSL：原生安装（官方推荐）
curl -fsSL https://claude.ai/install.sh | bash

# 有 Node.js 22+ 时也可以用 npm 全局安装
npm install -g @anthropic-ai/claude-code@latest

# Windows：WinGet 安装
winget install Anthropic.ClaudeCode
```

装完验证一下：

```bash
claude --version
# 正常会输出版本号，例如：2.1.329 (Claude Code)

# 更详细的安装与配置自检（只读诊断，不启动会话）
claude doctor
```

原生安装会自动在后台更新；Homebrew、WinGet 与 Linux 包管理器安装的需要手动更新（`claude update` 或走系统升级）。如果 `claude` 提示找不到命令，一般是安装目录没进 PATH，按官方文档的「Fix your PATH」处理。

### 步骤三：登录并开始第一个会话

```bash
cd /path/to/your/project
claude
```

首次运行会打开浏览器完成登录，按提示选你的账号类型：订阅账号走浏览器授权；设了 `ANTHROPIC_API_KEY` 环境变量并在提示时确认使用该密钥，就跳过登录直接按 API 计费。登录状态会被保存下来，下次直接进会话；想换账号或重新认证，在会话里输入 `/login`。

进会话后先试三句，感受它的工作方式：

```
解释一下这个项目的结构，入口文件是哪个
```

```
把 README 里的安装步骤按现在的代码核对一遍，有过时的地方列出来，先别改
```

```
帮我找一下用户登录失败时可能的原因，从代码里定位，不要猜
```

注意第二句的「先别改」：新手期养成「先让它说、你再点头」的习惯，比事后回滚便宜得多。

### 步骤四：第一个真正的改动

挑一个小任务练手，例如修一个已知的小 Bug 或加一个小功能：

```
修复登录页密码错误时提示文案不显示的问题，改完跑一遍相关测试
```

它会自己找相关文件、展示改动、征求你同意，改完跑测试、看结果再修。**审查改动时重点看 diff，不要只看它的文字总结。** 文字总结可能漏掉关键细节，diff 不会。满意就提交，不满意就让它按你的意见再改一轮。

### 步骤五：写好 CLAUDE.md，让它越用越懂你

这是性价比最高的配置。项目根目录新建 `CLAUDE.md`，写清四样东西：

```markdown
# 项目说明

这是一个用 Python + FastAPI 写的内部工具，后端在 `backend/`，前端在 `frontend/`。

## 常用命令

- 启动开发服务：`uv run uvicorn app.main:app --reload`
- 跑测试：`pytest tests/ -q`
- 检查格式：`ruff check .`

## 代码规范

- 新增接口必须补测试，测试文件放在 `tests/` 对应目录
- 不要引入新依赖，确有必要先说明理由
- 提交信息用中文，一句话写清改了什么

## 千万别碰

- 不要改 `migrations/` 下已发布的迁移文件
- 不要动生产配置文件 `prod.env`
```

写一次之后，每个新会话它都会读这份说明，犯低级错误的概率明显下降。项目变了就更新这份文件，相当于持续给它做入职培训。

### 步骤六：计划模式与检查点，大任务的安全带

任务越大，越不要让它直接动手。标准流程是两段式：

1. **先计划：**「先只读代码，给我一个实现方案，包括要改哪些文件、有什么风险，确认之后再动手。」它只读不改，你审方案。
2. **再执行：** 方案通过之后再让它动手，过程中用检查点兜底。Claude Code 会在关键步骤前自动保存检查点，改坏了可以回滚到之前的状态，不用手动 git reset。

权限模式用 `Shift+Tab` 随时切换：默认模式每步都问你；自动接受模式适合在已经提交过代码的分支上跑重复性任务，**不要在没提交的干净工作区里开自动接受**，出问题没有干净的回退点。

### 步骤七：常用命令速查表

| 命令 | 在哪里用 | 作用 |
| :--- | :--- | :--- |
| `claude` | 终端 | 在当前目录开始交互会话 |
| `claude "任务"` | 终端 | 启动会话并直接下达初始任务 |
| `claude -p "问题"` | 终端 | 问一个问题就退出，适合脚本调用 |
| `claude -c` | 终端 | 继续当前目录最近一次会话 |
| `claude -r` | 终端 | 恢复之前的某次会话 |
| `claude doctor` | 终端 | 只读检查安装与配置问题 |
| `/clear` | 会话内 | 开始新对话（旧对话可用 `/resume` 回来） |
| `/help` | 会话内 | 显示可用命令 |
| `/model` | 会话内 | 切换模型（Opus、Sonnet、Haiku） |
| `/usage` | 会话内 | 查看本次会话的 token 与费用估算 |
| `/login` | 会话内 | 切换账号或重新认证 |
| `/compact` | 会话内 | 压缩过长的对话上下文 |
| `/exit` 或连按两次 Ctrl+D | 会话内 | 退出 |

### 步骤八：进阶能力，按需开启

- **子代理：** 把「跑测试」「查文档」这类并行杂活派给子代理，主会话保持干净。简单任务用 Haiku 5.5 跑子代理更便宜。
- **MCP：** 接数据库、浏览器、第三方服务，让它能查真实数据而不是凭空编答案。先确认 MCP 服务的来源可靠再接。
- **自定义斜杠命令：** 把常用指令存成命令，例如 `/review` 跑一遍代码审查流程，以后一句话调用。
- **Hooks：** 在特定事件（例如改完文件、跑完测试）自动触发脚本，适合团队统一规范。
- **VS Code 与 JetBrains 扩展、桌面应用：** 不喜欢纯终端的人可以用编辑器扩展，同一套账号与计费。
- **Git 工作流：** 让它建分支、写提交信息、开 PR 都是常规操作，但提交之前你必须亲自看 diff。Anthropic 内部团队的用法可参考本站的 [Anthropic 内部怎么用 Claude Code](/posts/how-anthropic-teams-use-claude-code/)。

### 步骤九：费用控制三招

1. **随时看账：** 会话里输入 `/usage`，看当前会话的 token 与费用估算。API 用户看的是按标价算的估算，不是最终账单。
2. **简单任务降模型：** 用 `/model` 切到 Sonnet 5.5 做日常任务、Haiku 5.5 跑简单改动，输入输出都比 Opus 5.5 便宜一个量级。
3. **API 用户设上限：** 在 Console 里给工作区设消费上限；订阅用户则留意 5 小时与每周用量窗口，撞墙之后等窗口重置，不要反复重试刷额度。

## 4. 工业级避坑守则

### ⚠️ 避坑点 1：环境变量会悄悄改你的计费方式

如果 shell 里设了 `ANTHROPIC_API_KEY`，Claude Code 会在启动时问你要不要用这个密钥，一旦确认，**之后所有用量都按 API 计费，哪怕你同时付着 Pro 或 Max 订阅费**。不少人就是这样一边交订阅、一边又收到 API 账单。只想用订阅计费时，先检查并取消这个变量：

```bash
# 检查有没有设置
echo $ANTHROPIC_API_KEY

# 不用 API 计费时取消它，再进 claude
unset ANTHROPIC_API_KEY
```

### ⚠️ 避坑点 2：自动接受模式不要在没提交的代码上开

自动接受（auto-accept）确实爽，一路绿灯不用点确认；但它改坏的也是整片代码。铁律：**开自动接受之前先 `git add -A && git commit`**，留下一个干净的回退点；只在可丢弃的分支或实验项目里用。生产代码、没提交的工作区，一律用默认的逐项确认。

### ⚠️ 避坑点 3：上下文用完之前，先让它把进度写下来

长任务跑到一半，上下文窗口会越攒越满，表现先变差、最后可能直接断掉。正确做法是分段：一个任务拆成几步，每步结束让它把「做到哪了、下一步是什么」写进项目里的进度文件，再 `/compact` 压缩或 `/clear` 开新会话继续。不要等它自己断在半路，那时再补救最贵。

### ⚠️ 避坑点 4：别在脚本里写死旧模型 ID

模型会退役：**Claude Sonnet 4.5 将于 2026 年 11 月 30 日退役**，之后请求旧模型 ID 会直接报错，官方指定的替代是 Sonnet 5.5；Opus 4.8 的快速模式也在同一天移除。凡是在脚本、CI、定时任务里写死模型 ID 的地方，11 月 30 日之前改成 Sonnet 5.5 或 Opus 5.5。Claude Code 自己的默认模型会跟着官方走，一般不用手动管，但你的自动化脚本要自己检查。

### ⚠️ 避坑点 5：国内可用性，本文不下结论

Anthropic 官方安装文档要求用户位于其支持的国家/地区。中国大陆是否在支持名单内、国内网络能否直连、订阅付款走什么渠道，**本文没有实测，一律写「未证实」，不写「国内能用」「免费试用」这类结论**。订阅之前，先到官方支持国家名单与定价页确认你所在地区的可用性；已有账号的人也不要把账号借给他人登录，风控问题见本站的 [海外 AI 账号被封怎么办：申诉模板与预防清单](/posts/ai-account-ban-appeal/)。

## 5. 总结与后续行动建议

Claude Code 的价值不在「写代码更快」，而在「把整块任务交出去」：你描述目标，它读代码、定计划、改文件、跑测试、修报错，最后交给你审查。想真正用起来，按这个顺序走：

1. **今天就能做：** 按第 3 节装好、登录，用一个小项目跑通「解释结构 → 小改动 → 跑测试」三个任务。
2. **本周做：** 给主力项目写一份 `CLAUDE.md`，把常用命令与禁区写进去；大任务养成「先计划、再执行」的两段式习惯。
3. **长期做：** 简单任务切 Haiku 5.5、定期看 `/usage`；11 月 30 日之前检查脚本里的旧模型 ID；关注官方更新日志，Claude Code 的版本迭代非常快，本文写于 2026 年 11 月 21 日，命令与价格以官方文档为准。

## 常见问题

### 免费版 Claude 能用 Claude Code 吗？

不能。官方文档明确写着：免费版 claude.ai 不含 Claude Code，需要 Pro、Max、Ultra、Team、Enterprise 订阅其一，或 Claude Console（API）账号，或云厂商渠道。

### Claude Code 和 Cursor 会冲突吗？

不会，两者分工不同。Cursor 是你日常写代码的编辑器，强项是逐行补全与选中改片段；Claude Code 是终端里的任务执行者，强项是跨文件的大任务。常见组合是编辑器写日常代码、Claude Code 做重构修 Bug。已经订阅 Claude 的人用 Claude Code 不用再付费。

### 不会写代码的人能用 Claude Code 吗？

能做一些事，例如让它写小脚本、改博客配置、整理文件，但前提是你能看懂 diff、敢对改动说不。完全看不懂代码的人用它改重要项目风险很高，建议先从不重要的练手项目开始，或者先读本站的 [Claude 入门完整指南](/posts/claude-guide/) 了解 Claude 的基本用法。

### 费用失控怎么办？

三招：会话里用 `/usage` 随时看消耗；简单任务用 `/model` 切到 Haiku 5.5；API 用户在 Console 里设消费上限。订阅用户留意 5 小时与每周用量窗口，撞墙之后等窗口重置。

### 国内能注册订阅 Claude Code 吗？

未证实。Anthropic 要求用户位于其支持的国家/地区，中国大陆是否在列、付款渠道是否支持，本文没有实测，不下结论。订阅前先查官方支持国家名单与定价页，不要轻信第三方「包开通」的说法。

### Windows 能装吗？

能。官方支持原生 Windows（建议装 Git for Windows 以便用 Bash 工具）与 WSL 2 两种方式；WSL 2 支持沙箱，Linux 工具链的项目建议走 WSL。安装命令见第 3 节步骤二，细节以官方安装文档为准。
