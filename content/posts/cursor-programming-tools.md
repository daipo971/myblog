**结论先说：** Cursor 是目前用户最多的 AI 编程编辑器，界面和 VS Code 几乎一样，迁移成本很低。它最有价值的是三样：Tab 补全（预测你下一处要改的代码）、行内编辑（选中代码用自然语言修改）和 Agent（跨多个文件实现功能、运行命令）。免费版够轻度使用，每天写代码几小时的人值得开 Pro（$20/月）。「效率提升 10 倍」是营销说法，实际收益取决于任务类型：重复性的业务代码提升明显，架构设计和性能优化仍要靠人。

## Cursor 是什么

[Cursor](https://cursor.com/) 是 Anysphere 公司开发的代码编辑器，基于 VS Code 的开源版本改造，内置 AI 能力。因为底层是 VS Code，你原来的插件、快捷键、主题基本都能直接导入。

和「VS Code + AI 插件」相比，Cursor 的区别在于 AI 深度整合进编辑器：它会索引整个项目，补全和对话都能参考项目里的其他文件；AI 的修改以 diff 形式展示，可以逐处接受或拒绝。

**说明：** 本文依据 Cursor 官网、官方文档和更新日志整理（2026 年 10 月查阅），不包含长期实测数据。

## 核心功能

| 功能 | 怎么用 | 适合 |
| --- | --- | --- |
| Tab 补全 | 写代码时自动出现灰色建议，按 Tab 接受；还会预测下一处要改的位置 | 日常编码、重复模式 |
| 行内编辑 | 选中代码，按 Cmd/Ctrl+K，用自然语言描述要怎么改 | 改一个函数、加错误处理、改写法 |
| 对话 / Agent | 打开侧边栏（Cmd/Ctrl+I 或 Cmd/Ctrl+L），描述需求；Agent 模式下它会读文件、改多个文件、运行终端命令 | 实现功能、重构、排查 bug |
| @ 引用 | 在对话里输入 @ 引用文件、文件夹、文档、网页 | 精确控制 AI 看哪些内容 |
| 规则文件 | 在项目里写技术栈、规范和禁止事项 | 让 AI 每次都遵守项目约定 |

### Tab 补全

Cursor 的补全不只补当前行。例如你修改了函数参数，按 Tab 可以跳到调用这个函数的地方并给出对应修改。在写 CRUD、接口定义、组件属性等模式化代码时效果最明显。

### 行内编辑

选中一段代码后按 Cmd/Ctrl+K，输入「加上输入校验和错误处理」「改成异步写法」「补全类型注解」，它会在原地给出修改，确认后生效。这是最安全的用法，因为改动范围就是你选中的代码。

### Agent

Agent（早期叫 Composer）适合跨文件的任务，比如：

> 给用户模块加一个修改密码接口：在 routes 里注册路由，service 层校验旧密码并用 bcrypt 加密新密码，补充单元测试，改完运行 npm test。不要修改数据库结构。

写清楚 **要做什么、改动范围、不要动什么、怎么验证**，成功率会明显提高。Agent 改完后，逐个文件看 diff 再接受。

## 价格

| 档位 | 价格（官方） | 说明 |
| --- | --- | --- |
| Hobby | 免费 | 补全和 Agent 请求额度有限 |
| Pro | $20/月 | 额度大幅提高，可用更多高级模型 |
| Pro+ / Ultra | $60/月 / $200/月 | 重度用户的更高用量档 |
| Teams | $40/人/月 | 团队管理、统一计费和隐私设置 |

Cursor 的计费已从「按请求次数」改为「订阅费包含一定用量」，频繁使用最贵的模型时额度消耗会快很多。以 [官方价格页](https://cursor.com/pricing) 为准。学生可以先看 [学生党 AI 工具组合](/posts/student-ai-tools-2026/) 里的免费方案。

**值得开 Pro 的情况：** 每天写代码数小时、主要做业务开发、免费额度经常不够用。
**可以不开的情况：** 偶尔写脚本、主要做算法研究、已经在用其他 AI 编程工具。

## 上手配置

1. **下载安装**：从官网下载，首次启动时选择导入 VS Code 的插件和设置。
2. **登录账号**：用邮箱或 GitHub 登录，免费版即可开始。
3. **选择模型**：在设置里可以选择 Claude、GPT、Gemini 等模型；不确定时用默认的自动选择即可。
4. **打开隐私模式**（可选）：公司项目建议在设置里开启 Privacy Mode，并确认团队的安全规定。
5. **写规则文件**：在项目里添加规则文件（官方推荐放在 `.cursor/rules` 目录，旧版用根目录的 `.cursorrules`），例如：

```
技术栈：Next.js + TypeScript + Prisma + Tailwind
命名：文件名用小写中划线，函数用驼峰
要求：新增函数必须有类型注解；修改后运行 npm run lint
禁止：不要修改 prisma/migrations 下的已有文件
```

规则文件是性价比最高的配置，能显著减少 AI 写出不符合项目规范的代码。

## 适合和不适合的场景

| 适合 | 原因 |
| --- | --- |
| 新项目搭框架、写样板代码 | 模式化，AI 最擅长 |
| 读懂陌生代码库 | 可以对整个项目提问 |
| 修 bug、写测试 | 给出报错和上下文后定位快 |
| 学习新框架 | 边写边问，示例代码即时生成 |

| 不太适合 | 原因 |
| --- | --- |
| 复杂算法设计、性能关键路径 | 生成的代码能跑但不一定最优 |
| 系统架构决策 | 需要权衡业务、成本和团队情况 |
| 安全敏感代码（鉴权、加密、支付） | 必须人工逐行审查 |

一个常见误区是用「每天写了多少行代码」衡量效率。AI 能快速生成大量代码，但审查、测试和维护的成本也随之增加。更合理的衡量方式是功能交付周期和 bug 数量。

## 新手常见的坑

**1. 只用补全，不用行内编辑和 Agent。** 把 Cursor 当普通 VS Code 用，只能发挥很小一部分能力。

**2. 需求写得太模糊。** 「写一个登录功能」和「写一个登录接口，校验用户名密码，密码用 bcrypt 比对，成功返回 JWT，失败返回 401 和错误信息」，结果差别很大。

**3. 一次让 Agent 做太多事。** 大任务拆成几步，每步确认后再继续，出错时更容易回退。

**4. 不看 diff 直接全部接受。** AI 可能顺手改了你没要求改的地方，一定要逐个文件检查。

**5. 不用 Git。** Agent 修改前先提交一次，出问题可以一键回退。

**6. 忽略生成代码的安全问题。** AI 写的代码可能有 SQL 注入、越权、硬编码密钥等问题，上线前要审查。

## 常见问题

**Cursor 免费版够用吗？**
写练习项目、偶尔改代码够用。每天高强度使用 Agent 做多文件修改，额度会很快用完。

**Cursor 会上传我的代码吗？**
补全和对话需要把相关代码发送到服务端处理。开启隐私模式后，官方承诺不会用你的代码训练模型。公司项目使用前确认安全规定。

**国内能用 Cursor 吗？**
可以下载安装，但部分模型的访问可能不稳定；付费需要海外支付方式。

**Cursor 和 VS Code 插件冲突吗？**
绝大多数 VS Code 插件可以直接使用，少数依赖微软官方服务的插件可能不可用。

**新手学编程该用 Cursor 吗？**
可以用，但建议先自己写，卡住再让 AI 给提示。完全依赖 AI 生成代码，基础会很薄弱。
