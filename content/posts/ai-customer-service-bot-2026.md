**结论先说：** 想给网站或产品加一个能根据你的资料回答问题的 AI 客服，用开源平台 [Dify](https://dify.ai/) 是门槛最低的方案之一：上传 FAQ 和文档建成知识库，接一个大模型 API，生成嵌入代码贴到网站上即可。不想维护服务器就用 Dify 云端版；有 VPS 可以用 Docker 自部署。国内用户接 DeepSeek 或通义千问的 API，费用低、网络稳定。决定客服质量的不是模型，而是知识库整理得好不好，以及答不了时有没有转人工。

**说明：** 本文步骤依据 Dify 官方文档整理（2026 年 10 月查阅）。Dify 版本迭代快，界面名称可能有变化，以[官方文档](https://docs.dify.ai/)为准。

## 前置条件

| 项目 | 要求 |
| --- | --- |
| 资料 | 整理好的常见问题、产品说明、政策文档（Word、PDF、TXT、Markdown 或网页） |
| 模型 API | 任选一家：DeepSeek、通义千问、智谱、OpenAI、Anthropic 等的 API Key |
| 云端版 | 一个 Dify Cloud 账号即可 |
| 自部署 | 一台至少 2 核 4GB 内存的服务器，已安装 Docker 和 Docker Compose |
| 网站 | 能修改网页模板或插入 HTML 代码 |

还没有服务器的，可以参考 [低价 VPS 推荐](/posts/cheap-vps-recommendations-2026/)。获取模型 API 的方法见 [免费 AI API 指南](/posts/free-ai-api-guide/)。

## 第一步：选择云端版还是自部署

| 对比 | Dify 云端版 | Docker 自部署 |
| --- | --- | --- |
| 上手 | 注册即用 | 需要服务器和 Docker 基础 |
| 费用 | 有免费体验额度，正式使用需订阅 | 软件免费，付服务器和 API 费用 |
| 数据 | 存在 Dify 的云端 | 存在你自己的服务器 |
| 维护 | 无需维护 | 需要自己升级和备份 |

先用云端版跑通流程、验证效果，再决定要不要自部署，是比较省事的路线。

### 自部署步骤

```bash
git clone https://github.com/langgenius/dify.git
cd dify/docker
cp .env.example .env
docker compose up -d
```

启动后用浏览器访问 `http://服务器IP/install`，设置管理员账号。正式使用时建议绑定域名并配置 HTTPS，可以在前面加一层 Nginx 或使用 Cloudflare 代理。

## 第二步：接入大模型

进入 Dify 后台的「设置 → 模型供应商」，选择供应商并填入 API Key。

| 模型 | 适合 | 说明 |
| --- | --- | --- |
| DeepSeek | 国内中文客服 | 价格低，中文好，见 [DeepSeek 模型档案](/posts/deepseek-complete-guide-2026/) |
| 通义千问 | 国内中文客服 | 阿里云百炼平台提供 API |
| OpenAI / Claude | 海外用户、英文客服 | 需要海外支付方式 |
| 本地模型（Ollama） | 数据不出内网 | 需要较好的硬件，见 [本地运行大模型教程](/posts/ai-local-llm-guide-2026/) |

除了对话模型，知识库还需要一个 **Embedding（向量）模型** 用于检索，在同一页面配置即可，很多供应商同时提供。

## 第三步：建立知识库

在「知识库」中新建，上传文档或导入网页。

**整理资料的原则：**

1. **问答对优先。** 把最常见的 20–50 个问题写成「问题 + 标准答案」的形式，效果比直接丢整本说明书好得多。
2. **一个文件一个主题。** 发货、退换货、价格、账号问题分开放，便于检索和更新。
3. **删除过时内容。** 旧价格、旧政策会让 AI 给出错误答案。
4. **写清楚边界。** 比如「退款需人工审核，AI 不能承诺退款」。

**分段设置：** 使用默认的自动分段即可起步；如果发现回答经常只引用半句话，可以把分段长度调大，或者按标题手动分段。检索方式可以选择混合检索（关键词 + 向量），对产品型号、专有名词更准确。

## 第四步：创建客服应用

新建一个「聊天助手」类型的应用，关联刚才的知识库，然后写系统提示词：

```
你是{品牌名}的在线客服。请只根据知识库中的内容回答用户问题。
规则：
1. 知识库中没有的信息，回答「这个问题我需要转给人工同事确认」，并提供联系方式：{邮箱/微信}。
2. 不承诺退款、赔偿、发货时间等需要人工确认的事项。
3. 回答简洁，先给结论，必要时列步骤。
4. 不讨论与{业务范围}无关的话题。
```

需要更复杂的流程，比如先识别问题类型、再分别检索、无法回答时记录工单，可以改用 Dify 的工作流（Chatflow）编排。

## 第五步：测试

上线前一定要测试。列出 20 个真实用户最常问的问题，加上 5 个知识库里没有答案的问题、3 个故意刁难的问题，逐条检查：

- 有答案的问题是否答对、是否引用了正确的资料；
- 没答案的问题是否老实说不知道并转人工，而不是编造；
- 刁难问题（比如要求打折、套取内部信息）是否守住边界。

答错的问题，大多数时候应该修改知识库，而不是反复改提示词。

## 第六步：嵌入网站

在应用的「发布」页面选择嵌入网站，Dify 会生成一段 `<script>` 代码。把它粘贴到网站模板的 `</body>` 之前即可。

- **WordPress：** 用插入代码类插件，或放进主题的页脚模板。
- **Hugo、Hexo 等静态博客：** 放进主题的页脚模板（比如 Hugo 的 `layouts/partials/` 下对应文件）。
- **其他平台：** Dify 也提供 API，可以对接公众号、企业微信、Telegram、Discord 等，需要一定开发能力或借助社区插件。

## 常见报错与解决

| 现象 | 可能原因 | 解决 |
| --- | --- | --- |
| 自部署后打不开页面 | 端口被占用或防火墙未放行 80/443 | 检查 `docker compose ps`，放行端口，或修改 `.env` 中的端口 |
| 模型供应商保存失败 | API Key 错误、余额不足或网络无法访问该供应商 | 核对 Key 和余额；国内服务器优先用国产模型 |
| 知识库一直在「处理中」 | 未配置 Embedding 模型，或 worker 容器异常 | 配置 Embedding 模型，查看 `docker compose logs worker` |
| 回答和资料无关 | 检索没命中，或分段太碎 | 改用混合检索、调大分段、把常见问题写成问答对 |
| AI 编造答案 | 提示词没有限制，或知识库缺内容 | 在提示词中要求只依据知识库回答，补充缺失内容 |
| 网站上不显示聊天按钮 | 代码放错位置或被缓存 | 确认代码在 `</body>` 前，清除 CDN 和浏览器缓存 |

## 成本估算

| 项目 | 费用 |
| --- | --- |
| Dify 软件 | 自部署免费；云端版正式使用需订阅，见 [Dify 定价](https://dify.ai/pricing) |
| 服务器（自部署） | 2 核 4GB 的 VPS，按服务商价格 |
| 模型 API | 按 token 计费，国产模型的单次客服对话成本通常很低 |

实际花费主要取决于对话量和所选模型。上线初期可以在模型供应商后台设置用量上限，避免意外的高额账单。

## 零代码替代方案

不想部署任何东西，可以用 SaaS 客服工具：

- **Chatbase、Tidio 等：** 上传资料即可生成客服机器人，支持网站嵌入，按月订阅，数据存在第三方。
- **电商平台官方客服：** 在淘宝、京东、抖店等平台开店的，优先使用平台自带的智能客服，见 [电商卖家 AI 工具指南](/posts/ai-ecommerce-tools-2026/)。
- **国内智能体平台：** 扣子（Coze）等平台也能快速搭建知识库机器人并发布到多个渠道。

## 注意事项

- **隐私：** 不要把客户个人信息、内部敏感文档放进知识库。用户在对话中提供的信息也会发送给模型供应商。
- **合规：** 面向国内公众提供生成式 AI 服务有备案等监管要求，企业正式上线前咨询相关规定。
- **告知用户：** 在聊天窗口说明这是 AI 客服，并提供人工联系方式。

## 常见问题

**Dify 是免费的吗？**
Dify 是开源软件，自己部署不收软件费用，只需付服务器和模型 API 的费用。云端版有免费体验额度，正式使用需要订阅。

**不会编程能搭吗？**
用云端版不需要写代码，按界面操作即可；自部署需要会用 Linux 命令行和 Docker。完全不想碰技术的话，选 Chatbase、扣子这类零代码平台。

**AI 客服答错了怎么办？**
先看知识库里有没有正确答案：没有就补充，有但没检索到就调整分段和检索方式。同时在提示词里要求答不了时转人工，并定期抽查对话记录。

**能用在微信公众号里吗？**
可以通过 API 对接，但需要开发能力或社区插件。只是想快速试用的话，先嵌入网站验证效果。

**选哪个模型最好？**
中文客服用 DeepSeek 或通义千问性价比高；对回答质量要求高、预算充足，可以试更强的模型。客服场景下，知识库质量对效果的影响通常大于模型差异。
