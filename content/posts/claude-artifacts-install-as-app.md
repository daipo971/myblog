2026 年 11 月 24 日，Anthropic 发布了 Claude artifacts 的新功能「Install as app」：让 Claude 帮你做的工具，现在可以直接装成 Mac 或 Windows 上的桌面 App，beta 阶段向全部套餐开放。装好之后它有自己的图标、打开在自己的窗口里，而不是待在 Claude 的聊天框里。本文没有亲自安装测试，以下内容全部来自 Anthropic 官方公告与官方支持文档。

![插画：桌面上的独立应用窗口与 Dock 栏](/images/claude-artifacts-install-as-app/cover.webp)

## 一句话结论

以前 artifacts 是聊天里的一次性产出——一张图表、一个网页、一个小工具，用完就留在对话里。现在它可以变成一台电脑上的常驻应用：独立图标、独立窗口，能用你的连接器，能发通知，还能在菜单栏常驻。代价是必须联网并登录 Claude 才能打开，而且权限这件事得你自己把关，Anthropic 明确表示它不预审应用。

## 怎么装：两条路

官方给出的安装路径很简单。让 Claude 做一个 artifact 之后，在分享（Share）菜单里点「Install as app」即可。另一条路是 artifact 自己带安装按钮：做 artifact 的人可以在里面放一个安装按钮，你点它同样能装。无论走哪条路，Claude 都会先请你确认一次才会安装，不会悄悄装上。

安装之后，应用会出现在你的应用列表里，像其他应用一样打开。官方还提到，artifact 改了，装好的应用会自动跟着更新，不用重新安装。

需要先把 Claude 桌面端更新到新版本。官方支持文档没有写具体版本号，据 aiweekly 2026-11-24 的报道，Mac 或 Windows 需要 6.28899.0 或更高版本（该版本号来自第三方报道，未见于官方文档，以应用内实际提示为准）。更新方式：macOS 在 Claude 菜单点 Check for Updates，Windows 在 Help 菜单点 Check for Updates。

## 装完之后，它和聊天框里的 artifact 有什么不同

最大的变化是身份：它不再是对话里的一个附件，而是一个独立应用。具体有四点不同：

第一，独立图标和独立窗口。装好的应用有自己的图标，打开后在自己的窗口里运行，不用先打开 Claude 再翻聊天记录找它。

第二，可以用你的连接器。每个应用都可以使用 Claude 以及你接好的连接器，也就是说它不只是一个静态页面，而是能继续调用 Claude 能力的活应用。应用向 Claude 发的请求会计入你套餐的使用量，不需要单独的 API 密钥或另外登录，用你的 Claude 账号即可。

第三，可以发通知、可以常驻。经你允许，应用可以发通知，也可以在菜单栏（macOS）或系统托盘（Windows）加一个图标。带菜单栏或托盘图标的应用，关掉窗口后还会继续在后台运行；要彻底退出，macOS 从 Dock 退出或按 Cmd+Q，Windows 从托盘退出。

第四，不用打包、不用签名。传统上把一个网页工具变成桌面应用，至少要打包、签名、分发、处理更新。这里全都省了：不需要打包或签名，没有单独的登录环节，改了 artifact 就自动更新。

Anthropic 在官方公告里给了五个自家示例应用，展示这个功能能做成什么样：Linnet 是一个分层图片编辑器，Phosphor 是文件管理器，Sift 负责文件夹规则、让 Claude 持续帮你整理东西，Tern 是身边带着 Claude 的终端，Vitals 是可以从菜单栏或托盘快速查看电脑性能的小应用。

## 三档权限：这是最需要看明白的部分

装应用之前，真正要花时间理解的是权限。官方把权限分成三档，应用能干什么，取决于你给了哪一档。

第一档是默认权限。装好的应用只能做在浏览器里也能做的事。也就是说，一个网页能做什么，它就能做什么，不多不少。

第二档是应用权限。应用可以向你要一些受严格控制的功能，例如始终置顶的窗口、全局快捷键、通知。这一档是按需申请的，你可以逐项决定给不给。

第三档是完全访问（Full computer access）。这一档权限最大：应用可以运行程序，可以读取、修改、删除你的文件，而且之后每次都不用再问你。

> **安全提醒，先说在前面：Anthropic 在官方文档里明确写了，它不会在你安装之前审查应用，只给自己做的应用开「完全访问」。** 完全访问只能给自己做的应用；在 Team 或 Enterprise 套餐里，还可以给组织里其他人做的应用。权限只覆盖当前版本，应用每次更新之后，Claude 都会重新问你一遍，哪怕只是你自己改了 artifact。Team 和 Enterprise 的管理员可以在组织层面开关应用权限与完全访问。

这句话的实际意思是：别人分享给你的应用，默认不值得完全访问。如果一个陌生人做的应用一上来就要完全访问，最稳妥的做法就是拒绝。完全访问的正确对象只有你自己做的应用——你清楚它每一行逻辑、清楚它会碰哪些文件。

另外一个值得注意的细节来自 iClarified 的报道：应用里外部托管的组件可能在没有再次提示的情况下发生变化。这条来自第三方报道，未见于官方文档，但它和上一条是同一个道理——应用不是一成不变的，今天你检查过的应用，更新之后可能不一样。好在官方的规则补了一层：权限只覆盖当前版本，更新后会重新询问。

卸载也很直接：macOS 把应用移到废纸篓，Windows 移除它的快捷方式。带菜单栏或托盘图标的应用要先彻底退出再卸载，否则它还在后台跑着。

## 哪些情况装不了、打不开

不是所有 artifact 都能装。官方明确列出不能安装的类型，包括 Claude Docs、Slides 和 Sheets。其他 artifact 如果装不上，大概率是类型不在支持范围，可以先确认 artifact 本身是否支持安装。

打开应用有两个硬性条件：必须联网，必须登录 Claude Desktop。没有离线使用，断网或退出登录都打不开。这一点和传统桌面应用很不一样，装之前要先接受：它本质上还是一个连着 Claude 服务的应用，只是穿上了桌面应用的外衣。

套餐与组织方面也有开关：beta 阶段覆盖全部套餐；但 HIPAA 合规组织与混合部署（hybrid deployments）不能用。Team 套餐默认开启该功能，但完全访问默认关闭；Enterprise 套餐默认关闭，需要组织所有者手动开启。也就是说，企业用户能不能用、能用到哪一档，最终由管理员决定。

## 为什么值得关注

**以下为分析。** 这次发布表面上是个小功能，实际上是 artifacts 定位的一次升级，值得从三个角度看。

**第一，从「产物」到「软件」。** artifacts 最早的定位是工作的产出物：你让 Claude 做一张图表、一个网页，做完分享给别人，用完就留在对话里。现在它有了独立身份——图标、窗口、常驻后台。这改变了 artifact 的生命周期：以前是一次性的，现在可以长期放在桌面上、持续运行。对普通用户来说，「让 AI 帮我做个小工具」这件事，第一次有了落点：不再是聊天框里的一次演示，而是每天都能打开用的东西。

**第二，和传统打包方式比，门槛降到了「会说话」。** 以前把一个网页工具变成桌面应用，要走 Electron 打包、签名、分发、处理更新那一套，至少得是个开发者。现在不需要打包、不用签名、没有单独登录，改了 artifact 就自动更新。代价也很清楚：必须联网登录 Claude，没有离线；权限模型由 Claude 自己管，用户要自己判断该给多大权限。换句话说，Anthropic 把「做软件」的门槛降下来了，同时把「判断软件是否可信」的责任交给了用户。PWA 也能把网页装成应用，但 PWA 给不了全局快捷键、菜单栏常驻和完全访问这种系统级能力；Electron 能给，但要自己打包维护。Claude 这条路介于两者之间：能力比 PWA 深，成本比 Electron 低。

**第三，Claude 正在把 artifacts 变成软件分发入口。** 官方一次放出五个示例应用，覆盖图片编辑、文件管理、文件夹整理、终端、性能查看，像一个迷你应用商店的货架。但它没有商店、没有审核——官方明说不预审应用。这和苹果 App Store 的审核模式正好相反：分发去中心化了，分享链接就是分发渠道；风险也随之下放，用户自己判断。这对开发者是机会：一个原型可以直接变成可分发的应用，不用过商店审核、不用管打包签名。但对普通用户来说，判断成本变高了：以前在商店里下载应用，至少有一道审核；现在别人发来一个链接，点安装之前全靠自己判断。这也是为什么「只给自己做的应用开完全访问」这条官方警告值得放在正文最显眼的位置。

**第四，「不审核」能撑多久，是下一个观察点。** 官方现在把审核责任完全交给了用户，这在 beta 阶段说得通：用户量小、应用多是自用或小圈子分享，出问题的概率低。但如果分享链接真的变成主流分发渠道，恶意应用迟早会出现——一个伪装成文件整理工具的应用，要到完全访问之后能做的事，和任何恶意软件没有区别。到那时 Anthropic 有三条路：补一道安装前审核、做一个带评分与举报的应用目录、或者收紧完全访问的默认范围。官方现在已经埋了两个控制点：权限只覆盖当前版本、更新后重新询问，以及 Team 与 Enterprise 管理员可以在组织层面开关权限。这说明 Anthropic 知道风险在哪，只是选择先放开、再根据实际滥用情况收紧。同样值得观察的是开发者侧缺失的环节：现在只有制作与分享，没有发现机制、没有付费变现、没有版本管理之外的运营工具。一个原型能变成应用，但变成「产品」还差几步。如果后续补上应用目录或分享页，artifacts 就真的从功能升级成了平台；如果一直只有分享链接，它更可能停留在「高级用户的小工具」这个定位。

**第五，值得留意的是「常驻」这个动作本身。** 以前 artifact 用完就关，现在它可以挂在菜单栏、发通知、关了窗口还在后台跑，等于从「用一次的工具」变成了「一直在的工具」。这个变化很小，但它意味着 Claude 的产物开始跟原生应用抢注意力、抢桌面位置。官方示例里的 Vitals 很能说明方向：一个从菜单栏快速查看电脑性能的小应用，本身没有很复杂的功能，价值就在「随时在」。如果这条路走通，以后会有更多「一直在」的小工具：剪贴板、日程提醒、文件监控。反过来说，常驻能力也是最容易被滥用的地方：一个没什么用的应用一旦拿到通知与菜单栏权限，就能在你的桌面上一直刷存在感。装之前多问一句「它需要在后台一直跑吗」，能挡掉不少没必要的常驻应用。

综合来看，这个功能的真正意义不在「又多了一种装应用的方式」，而在 Claude 的角色变化：它正在从一个聊天助手，变成一个能产出软件、还能把软件送到你桌面上的平台。至于这个平台能不能长起来，关键看两件事：一是权限与安全机制能不能让普通用户放心，二是分享出去的应用有没有人持续维护更新。这两件事目前都还在 beta 阶段，值得继续观察。

## 常见问题

**免费版能用吗？**

能。官方口径是 beta 阶段覆盖全部套餐，不区分免费与付费。但应用向 Claude 发的请求会计入你套餐的使用量，免费版的用量上限同样适用。

**装完能离线用吗？**

不能。打开应用必须联网，并且登录 Claude Desktop。断网或退出登录都打不开。

**别人分享的应用能给完全访问吗？**

不能。完全访问只能给自己做的应用；在 Team 或 Enterprise 套餐里，还可以给组织里其他人做的应用。别人分享的应用，最多只能给到应用权限那一档。

**应用更新后，之前给的权限还在吗？**

不在。权限只覆盖当前版本，应用每次更新之后，Claude 都会重新询问，哪怕只是你自己改了 artifact。

**怎么卸载？**

macOS 把应用移到废纸篓，Windows 移除它的快捷方式。带菜单栏或托盘图标的应用要先彻底退出（macOS 从 Dock 退出或按 Cmd+Q），否则它还在后台运行。
