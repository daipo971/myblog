# 12 踩坑清单：2026-10 全站审计发现的问题

2026-10-28 对全站约 130 篇中文文章做了一次审计和清理。下面是发现的问题、为什么不行、以后怎么避免。
**写新文章、改旧文章之前先过一遍这份清单。** 能自动检查的已加进 `scripts/lint_posts.py`（标注「lint」）。

## 一、编造的经历和数据（最严重，约 45 篇）

| 问题 | 实际例子 | 为什么不行 |
| --- | --- | --- |
| 编造使用时长 | 「我每天用 ChatGPT 至少 5 小时」「花了半年摸索」「实测了两个月」，但网站 2026 年 7 月才上线 | 和网站年龄矛盾，读者和搜索引擎都能看出来；违反 CLAUDE.md「不写和发布时间矛盾的经历」 |
| 编造实验数据 | 「回复率从 3% 升到 18%」「各发 100 封邮件的对比表」「剪辑时间节省 66%」「准确率 85–90%」 | 没有真实数据支撑，一旦被质疑整站可信度受损 |
| 编造星级评分 | 每款工具 ⭐⭐⭐⭐⭐，没有测试方法 | 评测必须写测试方法和时间，没测就不能打分 |
| 编造个人故事 | 「上个月去日本玩了一周」「客户回复『你怎么知道的』」「我拿保温杯试了一下」 | 无法核实的故事等于虚构 |
| 编造作者身份 | 「15 年老程序员」「关于作者」段落 | 站长没有这样的身份 |
| 编造「本站已部署」 | 「我把客服机器人嵌入到博客」「我用 n8n 跑了两个月」 | 站上根本没有这些东西 |

**以后怎么做：**

- 没有亲自测试过，就写成客观整理，开头加一句「本文依据官网和文档整理（YYYY 年 MM 月查阅），不是实测打分」。
- 真的测试过：写明测试时间、环境、方法，附截图或原始输出，数据可复现。
- 耗时、效果类数字一律删掉，或写成「熟练后的大致估计」并说明不是测量结果。
- 「实测」二字只能出现在真有测试的文章标题里。
- lint：检测「用了 X 个月 / 半年」「我实测」「我每天用」「作为一个」「关于作者」等说法，给 WARN。

## 二、过期和错误的事实

| 问题 | 例子 | 正确做法 |
| --- | --- | --- |
| 已停服的产品还在推荐 | Sora（2026-03 宣布停止）、Tome 幻灯片（2025 年转型做 CRM） | 写之前查一次产品现状；档案页和对比页每季度复查 |
| 过时模型名当作当前产品 | GPT-4o、GPT-4o-mini、Claude 3.5、DALL-E 3 写成「最新」 | 写泛称（「ChatGPT 免费版」）或写当前型号并标查阅时间 |
| 免费额度、价格无来源 | 「免费每天 10 首」「Pro $19/月」 | 价格必须带官网链接；不确定就写「以官网为准」 |
| 技术事实错误 | 「Claude Code 跑在云端」「Codex 开源所以免费、代码不出电脑」「n8n 完全开源」「Dify 访问 3001 端口」「可以 API 自动发布到小红书」 | 对照官方文档写；代码和命令要能跑 |
| 版权与平台规则变化 | Suno、Udio 与唱片公司和解后下载规则改变 | 涉及版权、商用的段落写明时间和来源 |
| 发布时间错误 | 把 2025 年发布的 SDK 写成「2026 年推出」 | 写发布时间就附官方来源 |
| 让 AI 编数据的提示词 | 「列出搜索量最大的 10 个选题，附搜索量」 | 对话 AI 不知道真实搜索量、销量；提示词里要写「不要编造数据」 |

- lint：检测 GPT-4o、4o-mini、Claude 3.5、DALL-E 3 等旧名，给 WARN（文中说明「已过时」的可忽略）。
- lint：检测 Sora 出现在文中却没有「停」字的，给 WARN。

## 三、披露和变现

| 问题 | 例子 | 正确做法 |
| --- | --- | --- |
| 不实的联盟声明 | 22 篇文章没有任何联盟链接，结尾却写「有些链接是联盟链接……所有推荐都是我亲自用过」 | 只在真有联盟链接的文章写披露，放在第一个联盟链接之前，写清是哪个链接 |
| 推荐码不说明 | 免费域名教程的 `?ref=` 链接 | 推荐码、邀请码同样要披露 |

| 违反服务条款的建议 | 账号合租、共享账号、跨区套利、代充 | 不写；`海外服务通关` 只写官方渠道 |
| 代理、翻墙用途 | VPS 推荐里写「搭梯子」 | 不写 |

- lint：文中出现「联盟链接 / 佣金」声明但找不到 `aff=`、`ref=` 等链接时，给 WARN。

## 四、内容合规

- **学术诚信：** 不写「让 AI 写文献综述直接交」这类示例；涉及学生场景时提醒遵守学校的 AI 使用规定。
- **AI 内容标识：** 视频、图片类文章提醒《人工智能生成合成内容标识办法》（2025-09-01 施行）和平台的 AI 声明要求。
- **他人肖像和声音：** 数字人、声音克隆只能用本人或已授权的素材。
- **广告法：** 电商、营销类文章提醒极限用语和功效宣传的风险。
- **反垃圾邮件：** 开发信、批量发送类文章写明 CAN-SPAM、GDPR 等要求。
- **个人信息：** 正文里不放站长私人邮箱等联系方式，用评论区或网站联系页（待站长确认是否保留现有邮箱）。

## 五、结构和 SEO

| 问题 | 例子 | 正确做法 |
| --- | --- | --- |
| 同题重复 | 两篇「AI 省钱」、两篇视频生成对比 | 动笔前 `grep` 查重；合并后旧网址 301，删除旧文件 |
| 删除文章后留死链 | `ref` 短代码指向已删除文章导致构建失败 | 删除前 `grep -rn "旧slug" content` 改掉所有引用 |
| 改名后链接文字过期 | 站内链接仍用旧标题「实测 5 款」 | 改标题后全站搜旧标题替换 |
| 英文文章放在中文路径 | `best-free-ai-tools-2026`、`chatgpt-4o-free-guide-2026` | 英文只放 `.en.md`；中文路径只放中文 |
| 内容虚构的「月度更新」 | 「2026 年 7 月 AI 工具更新」写的是 Claude 3.5、GPT-4o 的旧功能 | 快讯必须有 ≥2 个一手来源；做不到就不写 |
| 文章太薄 | 教程 800 字、没有常见问题 | 按 CLAUDE.md 字数标准，教程 ≥2000 字并有 FAQ；表格不算正文字数 |
| 偏离定位 | Rust、高并发、模型量化等底层技术文 | 不再新写；存量待站长决定下线或改写 |
| 标签混乱 | 「AI工具」「2026年」这类无意义标签 | 只用 `data/taxonomy.yaml` 里的写法（lint 已检查） |
| 缺 lastmod、更新记录 | 改了内容但日期不变 | 每次实质修改都更新 `lastmod` 并在「更新记录」加一行 |

## 六、改写流程（以后照做）

1. 先读全文，列出：编造经历、过期事实、错误技术点、无来源数据、违规建议、失效链接。
2. 不能核实的删掉；能核实的补来源链接；过时的按官方最新信息改。
3. 开头 100 字内给结论，紧接一句「说明」交代信息来源和查阅时间。
4. 按类型补齐：常见问题、更新记录、站内链接（2 篇同支柱 + 1 个中心页或档案页）。
5. 标题和描述跟着内容改，去掉「实测」「试了回不去」这类与事实不符的说法；改名后全站替换链接文字。
6. 跑 `python3 scripts/lint_posts.py <文件>`，ERROR 为 0；构建后跑 `scripts/check_links.py`，死链为 0。
